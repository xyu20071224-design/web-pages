实验导览原第 1 页

Data Lab：用位运算解题。目的是让你熟悉位模式的表示方式 —— 整数、补码、浮点 —— 通过解 16 道编程「谜题」。

做什么

在 bits.c 里实现 16 个函数：6 道位运算、6 道补码算术、4 道浮点运算。很多谜题相当「人为」，但解它们的过程会让你真正开始用「位」思考。

怎么交

个人独立完成。全部通过 Autolab 电子提交，只提交 bits.c 一个文件。

怎么跑

在分配给你的 xLab 课程容器（Linux 节点）里做，地址 xlab.pku.edu.cn。

0.1 评分构成

每个实验满分 100 分。Data Lab 的原始分按 80 分制计算，最后线性换算到 100 分：

48 分 · 正确性

16 道谜题的难度评级在 1–4 之间，加权求和正好 48 分。整数题由 BDD 检查器穷举验证，浮点题由 btest 检查。

32 分 · 性能

按每个函数使用的运算符个数评分。每个「正确且满足运算符上限」的函数得 2 分，16 × 2 = 32 分。

最终分 = ⌈ 原始分 / 80 × 100 ⌉
关于「性能」的说明
老师关心的是你能得出正确答案，但同时也希望养成「尽量短小简洁」的习惯。有些谜题可以暴力求解，但希望你更聪明一点 —— 所以每个函数都有运算符上限。这个上限非常宽松，只为拦住那些离谱的低效解法。
交互：分数换算 + 提交次数惩罚

2. 编码规则原第 2 页

这是整个实验最容易丢分的地方：代码写对了但违反规则，一样得 0 分（只有当题目既符合全部编码规则、又通过正确性检查时才给分）。

2.1 整数谜题（位运算 6 题 + 补码算术 6 题）

  • 只能使用直线代码（straight-line code）：不允许循环、不允许条件语句。
  • 只能使用下面 8 个运算符：
!   ~   &   ^   |   +   <<   >>
  • 禁止使用超过 8 位的常量（即常量取值必须在 0x00–0xFF 之间）。
  • 部分函数会进一步限制可用运算符（例如 bitXor 只允许用 ~ 和 &）。
  • 每道题还有最大运算符个数限制，见下面各题的卡片。

2.2 浮点谜题（4 题）

这一部分规则放宽：

  • 允许使用标准控制结构（条件、循环），允许使用 int 和 unsigned 类型，允许任意整数常量。
  • 禁止使用 union、struct、数组。
  • 最关键的一条：禁止使用任何浮点数据类型、浮点运算或浮点常量。

浮点操作数会以 unsigned 类型传给你的函数，返回值也必须是 unsigned。也就是说，你要在位级别上实现这些浮点运算 —— 这正是这道题的意义。

2.3 交互：规则检查器

把你想写的表达式粘进来，先看看它是否合规、用了几个运算符（相当于在浏览器里跑一遍 dlc）。

2.4 dlc 的两个额外要求

① 不要在 bits.c 里包含 <stdio.h>
它会让 dlc 困惑并报出一些莫名其妙的错误。你仍然可以在 bits.c 里用 printf 调试（不包含头文件也能用），此时 gcc 会给出一个警告，忽略即可。
② 声明必须写在块的开头
dlc 对声明位置的要求比 C++/Java 甚至 gcc 都严格：在任何一个块（{ }）里， 所有声明必须出现在第一条非声明语句之前。下面这段会被 dlc 报错：
int foo(int x)
{
  int a = x;
  a *= 3;  /* 这条不是声明 */
  int b = a;  /* 错误：声明不允许出现在这里 */
}

3. 位运算谜题（6 题）原第 3 页 Table 1

每题都可以在页面里直接写表达式并跑测试。测试器会同时做三件事：规则检查（运算符白名单 / 常量位数 / 直线代码）、运算符计数、以及与参考实现对比跑几万到十几万个输入。

怎么用这些评测器
在「你的实现」里写表达式（只写表达式，不要写 return 和分号），点「测试」。测试覆盖边角值、全部 16 位取值、以及大量随机 32 位值；失败时会给出反例。如果你在 bits.c 里的写法与本页的变量名不同也没关系 —— 把变量对应过来即可。

关于答案：这里只给「思路提示」，不提供可直接粘贴的完整解答 —— 那是你的作业。评测器的作用是帮你验证自己的想法。

5. 浮点谜题（4 题）原第 3–4 页 Table 3

在这一部分，参数和返回值都是 unsigned，但它们的位模式代表浮点数。你必须完全用整数运算把浮点操作「做」出来。

两个约定（务必对照你的 bits.c 确认）
  • float_f2i：当参数是 NaN 或超出 int 范围时，按本实验惯例应返回 0x80000000。
  • float_negpwr2：手册只写了「Compute 2.0^(-x) at the bit level」，具体契约以 bits.c 注释为准。本页先按「x 是 0 ≤ n ≤ 127 的整数，返回 2^(-n) 的浮点位模式」实现，并把参考实现做成可编辑的 —— 你可以把它改成 bits.c 里的定义再测。

6. 工具链原第 3–7 页

handout 目录里带了四个工具：btest、dlc、BDD 检查器、driver.pl，外加两个可视化小工具 fshow 与 ishow。

6.1 btest：按值测试功能正确性

它用大量不同参数反复调用 bits.c 里的函数。注意：每次修改 bits.c 都必须重新构建 btest。

linux> make && ./btest          # 一步完成
linux> ./btest -f bitXor      # 只测一个函数
linux> ./btest -f bitXor -1 7 -2 0xf  # 只调用一次，x=7，y=15

建议一次只对付一个函数。-f 指定函数，-1/-2/-3 指定具体参数 —— 想插 printf 调试时就用这种单次调用，否则输出会太多。

6.2 dlc：检查编码规则

这是 MIT CILK 组改过的 ANSI C 编译器，用来检查每题是否符合编码规则。没有问题就静默通过；有非法运算符、运算符超限、或整数题里出现非直线代码才会报错。

linux> ./dlc bits.c       # 静默 = 通过
linux> ./dlc -e bits.c    # 打印每个函数用掉的运算符个数
linux> ./dlc -help

6.3 BDD 检查器：穷举验证（整数题）

btest 只是抽样测试；对大多数函数来说，参数组合数远超能抽样的范围。为此实验提供了形式化验证程序 cbit，它用 二元决策图（BDD）穷举所有参数组合。

linux> ./bddcheck/check.pl -f fun  # 检查一个函数
linux> ./bddcheck/check.pl       # 检查全部
linux> ./bddcheck/check.pl -g     # 检查全部并给出紧凑的表格汇总
BDD 检查器的两个挑剔之处
  • 不能处理调用其它函数的函数（包括 printf）。带 printf 调试的版本只能用 btest 测；提交前务必删掉这些调试语句。
  • 对格式很挑：函数必须以 int fun (...) 或 unsigned fun (...) 这样的一行开头，并以最左列的一个右花括号结束 —— 而且最左列只能有这一个右花括号。

6.4 driver.pl：算总分

它调用 dlc 和 BDD 检查器，算出你的正确性分与性能分。Autolab 自动评分用的就是这个程序。

linux> ./driver.pl

7. 自测流程与提交原第 6–8 页

7.1 推荐的自测顺序

一次只测一个函数，按下面五步走：

Step 1 · 单点调试
./btest -f bitXor -1 23 -2 0xabcd
用 -f 配合 -1/-2 只调用一次。可以放心用 printf 打印中间变量，但调试完记得删掉。
Step 2 · 大量取值
./btest -f bitXor
与大批输入对比。若报错，btest 会打印出失败的具体参数 —— 带着这些参数回到 Step 1 调试。
Step 3 · 规则检查
./dlc bits.c
静默即通过。加 -e 可以看到每个函数的运算符个数。
Step 4 · 穷举验证
./bddcheck/check.pl -f bitXor
整数题在通过 btest 后，用 BDD 检查器做最终的（穷举）正确性验证。注意：浮点题由 btest 评分，不走 BDD。
Step 5 · 算总分
./driver.pl
对每个函数重复 1–4 步；随时可以跑 driver 看当前累计的正确性分与性能分。
一个小习惯
每次 make 之前先 make clean。

7.2 提交规则

  • 每个实验的提交次数上限 16 次；超过后每次提交扣本实验 5% 的分数。
  • 扣分上限为 80%（即最多 16 次额外提交）。
  • 如果提交了 32 次，之后的提交将不再受理。
  • 用 Autolab 的「Handin your work」上传 bits.c。服务器会跑 driver 程序生成成绩报告，并发布到排行榜。
  • 每次提交都会被归档，随时可用「View handin history」查看。
提交注意事项
  • 任何时候，你最近上传的文件就是你的正式提交。可以随时提交。
  • 每次提交后，用「View your handin history and scores」确认自动评分正常完成（页面需手动刷新）。
  • 提交前必须删掉 bits.c 里所有多余的打印语句。
