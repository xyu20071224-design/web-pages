一句话核心

计算机里只有位。同一个位模式，按不同的类型去解释，就得到不同的值 —— 本讲几乎所有的「坑」都源于此。

位模式 0xC4 0x93
→ int16: −15213
→ uint16: 50323

1.2 字节与十六进制

  • 字节（byte）= 8 位（bit）。
  • 一个字节的二进制范围：000000002 到 111111112；十进制 010 到 25510；十六进制 0016 到 FF16。
  • 十六进制（base 16）用 0–9 和 A–F 表示。
  • 在 C 里写作 0xFA1D37B 或 0xfa1d37b（大小写都行）。

为什么十六进制好用？因为一个十六进制位正好对应 4 个二进制位，所以 1 字节 = 2 个十六进制位，读写和口算都方便。

2. 位级运算原第 7–12 页

布尔代数只有四个运算，但它们构成了计算机里所有逻辑运算的基础。

2.1 布尔代数

19 世纪由 George Boole 提出，是逻辑的代数表示：把「真」编码为 1、「假」编码为 0。

交互：切换 A、B，四张真值表里对应的行会高亮

2.2 位向量：把一组位当成一个整体

运算逐位进行（bitwise）：

01101001   01101001   01101001   ~01010101
& 01010101   | 01010101   ^ 01010101
01000001   01111101   00111100   10101010

用位向量表示集合

宽度为 w 的位向量可以表示集合 {0, …, w−1} 的子集：第 j 位为 1 就表示 j 在集合里。于是位运算正好对应集合运算：

位运算集合含义课件例子
&交集 Intersection01000001 → {0, 6}
|并集 Union01111101 → {0, 2, 3, 4, 5, 6}
^对称差 Symmetric difference00111100 → {2, 3, 4, 5}
~补集 Complement10101010 → {1, 3, 5, 7}

其中 01101001 = {0, 3, 5, 6}、01010101 = {0, 2, 4, 6}。位是从右往左编号 7…0 的，别数反了。

2.3 C 中的位运算

&、|、~、^ 可用于任何「整型」数据类型（long、int、short、char、unsigned）：把参数看作位向量，逐位运算。

C 表达式（char）二进制结果
~0x41~010000012 → 1011111020xBE
~0x00~000000002 → 1111111120xFF
0x69 & 0x55011010012 & 010101012 → 0100000120x41
0x69 | 0x55011010012 | 010101012 → 0111110120x7D

2.4 对比：C 中的逻辑运算

逻辑运算 &&、||、! 和位运算完全是两回事：

  • 0 表示「假」，任何非 0 值表示「真」；
  • 结果永远是 0 或 1；
  • 会短路求值（early termination）：a && b 里如果 a 为假就不再计算 b。
C 表达式（char）结果说明
!0x410x000x41 非 0 → 真，取非得假
!0x000x010 是假，取非得真（注意结果是 1 而不是 0xFF）
!!0x410x01把任意非 0 值规范化成 1
0x69 && 0x550x01两者都非 0 → 真
0x69 || 0x550x01两者都非 0 → 真
最常见的笔误之一
把 && 写成 &（或把 || 写成 |）。0x69 & 0x55 得到 0x41（非 0 仍是真，可能侥幸不出错），而 0x01 & 0x02 得到 0（假），但 0x01 && 0x02 却是真 —— 二者并不等价。

另一个典型用法是 p && *p：先判断指针非空，再解引用，利用短路避免空指针访问。

2.5 移位运算

左移 x << y
  • 把位向量 x 向左移 y 位；
  • 左边多出来的位丢弃；
  • 右边补 0。
右移 x >> y
  • 右边多出来的位丢弃；
  • 逻辑右移：左边补 0；
  • 算术右移：左边复制最高位（符号位）。
未定义行为
移位量 < 0 或 ≥ 字长时，C 标准规定行为未定义。例如对 32 位 int 写 x >> 32 是错的（不同编译器结果可能不同）。

3. 整数的表示原第 14–19 页

同一串位，用「无符号」和「补码」两种方式解释，会得到两个不同的整数。

3.1 无符号与补码

无符号（Unsigned）
B2U(X) = Σi=0..w−1 xi × 2i

每一位都按正的 2 的幂加权求和。

补码（Two's Complement）
B2T(X) = −xw−1 × 2w−1 + Σi=0..w−2 xi × 2i

最高位带负权 −2w−1，其余位同无符号。最高位因此也叫符号位。

符号位：补码的最高位表示正负 —— 0 表示非负，1 表示负数。

课件例子（short，2 字节）
short int x =  15213;  → 十进制 15213   十六进制 3B 6D   二进制 00111011 01101101
short int y = −15213;  → 十进制 −15213   十六进制 C4 93   二进制 11000100 10010011

注意 x 与 y 的位模式「按位取反再加一」互为相反数：~(0x3B6D) + 1 = 0xC493。

3.2 补码的直观理解：带正负号的权重

用 5 位来举例，最高位权重是 −16，其余是 8、4、2、1：

4. 转换与强制类型转换原第 21–28 页

有符号与无符号之间的转换规则只有一句话：位模式不变，只是重新解释。但它的后果常常出人意料。

4.1 映射的方向

补码 x  —T2B→  位模式 X  —B2U→  无符号 ux
无符号 ux  —U2B→  位模式 X  —B2T→  补码 x

两条路径都保持相同的位模式（Maintain Same Bit Pattern），只是换了套解释规则。

4.2 数学关系（T2U）

ux = x + 2w  (x < 0)
x          (x ≥ 0)

道理很简单：最高位在补码里是「大负权」−2w−1，在无符号里是「大正权」+2w−1，一进一出正好差 2w。

交互：T2U / U2T 转换器

4.3 转换的可视化：顺序被「折断」

把补码映射到无符号时，负数段整体平移到了大正数区，于是数值大小顺序发生了反转：

所以 TMax < TMin 之类的「怪事」就出现了：转换成无符号后，最小的负数变成了最大的正数（−1 → UMax）。这就是后面所有比较运算陷阱的来源。

4.4 C 中的有符号与无符号

  • 常量默认视为有符号整数；带后缀 U 的才是无符号，如 0U、4294967259U。
  • 显式转换：(int) ux、(unsigned) ty，效果就是 U2T 和 T2U。
  • 隐式转换：赋值和函数调用时也会发生，如 tx = ux;、uy = ty;。
表达式求值规则（最重要的一条）
如果一个表达式里同时出现有符号和无符号，那么有符号值会被隐式转换成无符号 —— 包括 <、>、==、<=、>= 这些比较运算。

4.6 小结：有符号 ↔ 无符号的基本规则

  • 位模式保持不变，但被重新解释。
  • 效果可能出乎意料：相当于加上或减去 2w。
  • 含 int 与 unsigned 的表达式里，int 会被转成 unsigned。

5. 扩展与截断原第 30–34 页

把数从窄类型搬到宽类型（扩展）或反过来（截断），位模式会怎么变？

5.1 符号扩展（Sign Extension）

任务：给定 w 位有符号整数 x，把它转成 w+k 位但数值不变。

规则：在最左边复制 k 份符号位：X' = xw−1, …, xw−1, xw−1, xw−2, …, x0。

符号5 位6 位（扩展后）
正数0 1 0 1 0 = 100 0 1 0 1 0 = 10
负数1 0 1 1 0 = −101 1 0 1 1 0 = −10

为什么负数补 1 也对？因为新补上的最高位是 −2w+k−1，而原来的最高位变成 +2w+k−2，两者相加正好等于原来的 −2w−1。

5.2 课件原例：short → int

变量十进制十六进制二进制
short x152133B 6D00111011 01101101
int ix1521300 00 3B 6D00000000 00000000 00111011 01101101
short y−15213C4 9311000100 10010011
int iy−15213FF FF C4 9311111111 11111111 11000100 10010011

把窄类型赋给宽类型时，C 会自动做符号扩展。

5.3 截断（Truncation）

把 w 位截成 k 位：丢掉高 w−k 位，剩下的位按新类型重新解释。数值上等价于取模：

x' = x mod 2k（无符号）    x' = U2T(x mod 2k)（有符号）
情形5 位4 位（截断后）说明
符号不变0 0 0 1 0 = 20 0 1 0 = 22 mod 16 = 2
符号改变0 1 0 1 0 = 101 0 1 0 = −610 mod 16 = 10U = −6
负数1 1 0 1 0 = −61 0 1 0 = −6−6 mod 16 = 26U mod 16 = 10U = −6
负数变正1 0 1 1 0 = −100 1 1 0 = 6−10 mod 16 = 22U mod 16 = 6
交互：扩展 / 截断工具

5.4 小结：扩展与截断的基本规则

扩展（如 short int → int）
  • 无符号：左侧补 0；
  • 有符号：符号扩展；
  • 两者都能得到预期结果。
截断（如 unsigned → unsigned short）
  • 无论有无符号，都是直接丢弃高位；
  • 结果重新解释；
  • 无符号：相当于取模；有符号：类似取模。

6. 整数运算原第 36–50 页

计算机的整数加法不具备「数学加法」的全部性质 —— 因为它会溢出并默默地绕回来。

6.1 无符号加法：丢弃进位的模运算

操作数：w 位   u
           +  v
真和：w+1 位   u + v
丢弃进位：w 位   UAddw(u, v)

标准的加法电路就是忽略进位输出，所以它实现的是模运算：

s = UAddw(u, v) = u + v mod 2w
课件例子（unsigned char，8 位）
  1110 1001   E9   233
+ 1101 0101   D5   213
1 1011 1110   1BE   446  ← 真和
  1011 1110   BE   190  ← 丢弃第 9 位后的结果
交互：加法器（无符号 / 补码，含溢出判定）

6.2 溢出的两种方向

无符号：只有一种「环绕」

真和 ≥ 2w 时，结果绕回到小值段。最多绕一次。

补码：两个方向都可能溢出
  • 正溢出 PosOver：和 ≥ 2w−1，结果变成负数；
  • 负溢出 NegOver：和 < −2w−1，结果变成正数；
  • 同样最多各发生一次。

6.3 补码加法与无符号加法的关系

两者在位级上的行为完全相同：都是「正常相加后丢弃最高进位」。差别只在于最后怎么解释结果的位模式。

int s, t, u, v;
s = (int) ((unsigned) u + (unsigned) v);
t = u + v    // 一定有 s == t
课件例子（8 位补码）
  1110 1001   E9   −23
+ 1101 0101   D5   −43
1 1011 1110   1BE
  1011 1110   BE   −66   ✓ 正好在范围内

6.4 TAdd 的分段公式

TAddw(u, v) = u + v + 2w   当 u + v < TMinw  （负溢出）
u + v            当 TMinw ≤ u + v ≤ TMaxw
u + v − 2w   当 TMaxw < u + v  （正溢出）

换句话说：先按数学算，如果超界就加一次或减一次 2w把它拉回可表示范围内。

6.5 乘法

两个 w 位整数相乘，精确结果可能需要 2w 位：

  • 无符号：最多 2w 位，范围 0 ≤ x·y ≤ (2w−1)2 = 22w − 2w+1 + 1。
  • 补码最小值（负）：最多 2w−1 位，x·y ≥ (−2w−1)(2w−1−1) = −22w−2 + 2w−1。
  • 补码最大值（正）：最多 2w 位，但只有 (TMinw)2 这一个取值会达到。

所以要做到「精确」，字长必须随每次乘法不断加宽 —— 这由软件实现，例如各种任意精度算术库。

而在 C 里，乘法丢弃高 w 位，只保留低 w 位：UMultw(u,v) = u·v mod 2w。有符号与无符号的高位不同，但低位完全相同。

类型算式十六进制解释
无符号233 × 213 = 49629C1DD → DD221（49629 mod 256）
补码−23 × −43 = 98903DD → DD−35

注意两行的结果字节都是 DD，但解释成有符号时是 −35、无符号时是 221。

交互：乘法器（看到 2w 位真积如何被截断）

6.6 乘以 2 的幂：左移

u << k  等价于  u × 2k
  • 有符号、无符号都成立；
  • u << 3 == u * 8
  • (u << 5) − (u << 3) == u * 24（24 = 32 − 8，用移位加组合出乘法）
重要的一课：相信你的编译器
大多数机器上移位加比乘法快，而编译器会自动把「乘以常数」优化成移位与加法的组合。所以不要手写这种优化，写出 u * 24 就好。

6.7 除以 2 的幂：右移

无符号数用逻辑右移：u >> k 得到 ⌊u / 2k⌋（向下取整）。

运算精确值结果十六进制二进制
x15213152133B 6D00111011 01101101
x >> 17606.576061D B600011101 10110110
x >> 4950.812595003 B600000011 10110110
x >> 859.42578135900 3B00000000 00111011
有符号数不能直接这么用
对负数，算术右移是向下取整（朝 −∞），而 C 的除法是向零取整。例如 −1 >> 1 = −1，但 −1 / 2 = 0。编译器若要用移位实现有符号除法，必须先加一个偏置（如 (x + (1<<k) − 1) >> k）。
交互：移位 = 乘除 2 的幂（观察有符号除法的差异）

6.8 算术运算的基本规则

加法
  • 无符号/有符号：正常相加后截断，位级操作相同；
  • 无符号：模 2w 加法（数学加法，可能减去一次 2w）；
  • 有符号：修正后的模 2w 加法（结果落在正确范围），数学加法，可能加上或减去一次 2w。
乘法
  • 无符号/有符号：正常相乘后截断，位级操作相同；
  • 无符号：模 2w 乘法；
  • 有符号：修正后的模 2w 乘法。

7. 该不该用无符号？原第 51–53 页

无符号不是「更安全的写法」。不懂它的语义就用，只会埋下更隐蔽的 bug。

7.1 陷阱一：用无符号倒着循环

✗ 错误写法
unsigned i;
for (i = cnt-2; i >= 0; i--)
    a[i] += a[i+1];

无符号数永远 ≥ 0，所以 i >= 0 恒为真。当 i 减到 0 再减 1 时，它会绕回 UMax，循环变成死循环。

✓ 正确写法
unsigned i;
for (i = cnt-2; i < cnt; i--)
    a[i] += a[i+1];

用 i < cnt 作条件：绕回后 i 变成 UMax，必然不小于 cnt，循环正常结束。

为什么这是「有保证」的
C 标准保证无符号加法是模运算：0 − 1 → UMax。所以依赖这个回绕来终止循环是合法且可移植的。参见 Robert Seacord《Secure Coding in C and C++》。

更好的写法是用 size_t：它的长度等于机器字长，即使 cnt = UMax 也能正常工作。
（想一想：如果 cnt 是有符号且小于 0，这段代码会怎样？）

交互：循环模拟器（看它到底跑多少次）

7.2 什么时候该用无符号

✓ 做模运算时

例如多精度算术（multiprecision arithmetic）：你要的正是「回绕」语义。

✓ 用位表示集合时

需要逻辑右移（左侧补 0，不做符号扩展），无符号正合适。

结论
不懂就别用。大多数情况下有符号更安全；只有在明确需要模运算或位集合语义时才用无符号。

8. 内存中的表示原第 55–66 页

程序按地址访问数据。多字节数据在内存里的排列顺序（字节序）依机器而异 —— 这是跨平台 bug 的经典来源。

8.1 面向字节的内存组织

  • 程序通过地址引用数据。可以想象内存是一个非常巨大的字节数组，地址就是数组下标；指针变量存的就是地址。
  • 系统为每个「进程」（正在执行的程序）提供私有的地址空间，所以程序可以破坏自己的数据，但碰不到别的进程的。

8.2 机器字长

32 位字长

整数与地址的名义宽度都是 32 位（4 字节），地址空间上限 4 GB（232 字节）。

64 位字长

可寻址内存理论上可达 18 EB（18.4 × 1018 字节）。

机器仍然支持多种数据格式，但都是字长的分数或整数倍，并且永远是整数个字节。

字与地址的关系：一个字的地址 = 其中第一个字节的地址；相邻字的地址相差 4（32 位）或 8（64 位）。

8.3 字节序（Byte Ordering）

大端 Big Endian

Sun、PowerPC Mac、互联网。
最低有效字节放在最高地址。

小端 Little Endian

x86、ARM（跑 Android / iOS / Windows 时）。
最低有效字节放在最低地址。

课件例子
变量 x 是 4 字节的值 0x01234567，地址 &x = 0x100：
大端： 0x100: 01   0x101: 23   0x102: 45   0x103: 67
小端： 0x100: 67   0x101: 45   0x102: 23   0x103: 01
交互：字节序可视化 + show_bytes 模拟

8.4 整数的内存表示（课件原例）

十进制 15213 = 二进制 0011 1011 0110 1101 = 十六进制 3B 6D。把这个值放进内存，不同的机器会排出不同的字节顺序：

交互：15213 / −15213 在各平台下的字节序列

8.5 show_bytes：把数据的字节打出来

把指针强制转换成 unsigned char *，就可以把任意数据当成字节数组来查看：

typedef unsigned char *pointer;

void show_bytes(pointer start, int len) {
    int i;
    for (i = 0; i < len; i++)
        printf("%p\t0x%.2x\n", start+i, start[i]);
    printf("\n");
}

printf 的格式：%p 打印指针，%x 打印十六进制。

执行示例（Linux x86-64）
int a = 15213;
0x7fffb7f71dbc  6d
0x7fffb7f71dbd  3b
0x7fffb7f71dbe  00
0x7fffb7f71dbf  00

低字节 6d 在低地址 → 小端。地址本身每次都不同，但字节顺序是稳定的。

8.6 指针与字符串

指针
  • 不同编译器、不同机器会给对象分配不同位置；
  • 甚至同一程序每次运行结果都不同（地址空间随机化）。
字符串
  • C 里字符串是字符数组，每个字符用 ASCII 编码（7 位字符集）；
  • 字符 "0" 的编码是 0x30，所以数字字符 i 的编码是 0x30 + i；
  • 字符串必须以 null（0）结尾；
  • 字节序与字符串无关（每个字符只占 1 字节），所以跨平台兼容。
课件例子：char S[6] = "18213";

8.7 读懂反汇编里的字节序

反汇编（disassembly）是机器码的文本表示。看到 add $0x12ab,%ebx 时，指令里那 4 个字节其实是这样来的：

步骤结果
取值0x12ab
补齐到 32 位0x000012ab
按字节拆开00 00 12 ab
反转（小端）ab 12 00 00  ← 这就是机器码里的顺序
