1. 炸弹是什么原第 1 页

邪恶的 Mr. Gin 在我们的 64 位 Linux 机器上安放了一大批二进制炸弹（binary bomb）。所谓二进制炸弹，是一个由一连串阶段（phase）组成的程序：每个阶段都要求你在标准输入（stdin）上敲入一个特定的字符串。敲对了，这个阶段就被拆除（defuse），炸弹进入下一阶段；敲错了，炸弹就爆炸（explode）——打印 "BOOM!!!" 然后终止。当每个阶段都被拆除，炸弹就被拆除了。

一个阶段的生死循环

读入一行输入 → phase_N 校验 → 字符串正确：拆除本阶段，进入下一阶段；字符串错误：explode_bomb → 打印 "BOOM!!!" → 程序终止。

炸弹太多，我们来不及逐颗处理，所以给每位学生发一颗。你无可选择、必须接受的任务，就是在截止日期前拆掉你的炸弹。我们相信，你和柯南一样，也在夏威夷进修过炸弹处理。祝你好运，欢迎加入拆弹小队！

3. 第二步：拆除炸弹原第 2–3 页

本实验的任务只有一个：拆掉你的炸弹。

必须在 xLab 容器里做
登录 xlab.pku.edu.cn 打开你的容器（浏览器终端、Web VS Code、VS Code Remote 或 SSH——见你的 node 页面，或问助教）。有传闻说 Mr. Gin 是真邪恶：炸弹只要换地方跑就总是爆炸——它只能在连得上课程服务器的地方被拆除，也就是你的 xLab 容器。据说里面还装了好几道别的防拆装置。

拆弹工具随你挑（§6 有清单和提示）。最好的办法，是用你顺手的调试器在反汇编出来的二进制上单步执行。

3.1 计分规则

炸弹每爆炸一次，就会通知一次 Autolab 服务器，你的实验最终成绩扣 0.5 分（最多扣 20 分）。所以爆炸是有后果的——务必小心！前四个阶段每关 15 分；第 5、6 关稍难，各 20 分。所以你能拿到的最高分是 100 分。

虽然阶段一个比一个难，但你在逐关推进中积累的本领应当能抵消难度。不过最后一关对最好的学生也是个挑战——别拖到最后一刻才开始。

交互：计分器——勾掉已拆的阶段、填上爆炸次数，实时算分

3.2 答案文件与安全退出

炸弹会忽略空输入行。如果带命令行参数运行，例如：

linux> ./bomb psol.txt

它会先从 psol.txt 逐行读取输入，直到 EOF（文件结束），然后转回标准输入。Dr. Evil 一时心软，加了这个功能，免得你反复重输已拆阶段的答案。

想避免误爆，你需要学会两件事：单步执行汇编代码、设置断点。任何时候都可以按 ctrl-c 安全退出（同时按下 ctrl 与 c）。

你还需要学会查看寄存器与内存状态。做这个实验的一个副产品是：你的调试器水平会突飞猛进——这是一项会用一辈子的关键技能，回报巨大。

警告：不要用调试器直接跳到某个阶段
这么做可能导致炸弹无声地爆炸——你连 "BOOM!!!" 都看不到，分却照扣。

4. 提交与记分板原第 3 页

没有显式的提交动作。炸弹会在你拆弹的过程中自动把进度上报给 Autolab。想知道自己进展如何，去看 Autolab 的班级记分板：从 Autolab 进入 Bomblab -> View scoreboard。该页面持续更新，实时显示每颗炸弹的进度。

5. 提示：请勿暴力破解原第 3–4 页

拆弹的路子很多，但有一条被课程组明确劝退：暴力穷举。

拆弹可以完全不动手运行程序，纯靠静态分析把它研究个底朝天，弄清它到底做什么——这招有用，但不总容易。也可以在调试器里跑，一步步盯着它做什么，再用这些信息把它拆掉——这通常是最快的路。

我们确实有一个请求：请勿使用暴力法！你完全可以写个程序把所有可能的钥匙挨个试一遍，但这条路走不通，原因有四：

扣分
每猜错一次、炸弹爆炸一次，就扣 0.5 分（最多扣 20 分）
穷举到一半，分已经扣穿了。
封号
每次猜错都会向 Autolab 服务器发一条消息
很快就会把网络塞满，系统管理员可能会收回你的计算机使用权限。
天文数字
即使假设每串不到 120 个字符、只含字母，每阶段也有 26120 种猜测
这还是个（并不成立的）假设——课程组没告诉你字符串多长、由什么字符组成。要跑非常非常久，截止日期前你绝算不完。
字符集受限
phase_5 的答案只能由数字与字母组成！
含不支持字符的输入可能引发奇怪的结果，课程组概不负责。
交互：暴力破解不可行性计算器——亲手算算课程组说的 26120 有多离谱
别忘了 phase_5 的字符集约束
第 4 条提示是难得的官方情报：phase_5 的答案只由数字与字母组成。在页内计算器里把字符集大小设成 36 再感受一下——就算知道字符集，穷举依然不可行。

6. 侦察工具箱原第 4 页

很多工具能帮你搞清程序怎么工作、出了错又是为什么。下面是分析炸弹时最趁手的几件。

gdb —— GNU 调试器

几乎所有平台都有的命令行调试器。可以逐行跟踪程序、查看内存与寄存器、对照汇编代码（炸弹的大部分源码我们是不给的）、设置断点、设置内存观察点、写脚本。

CS:APP 教材网站（http://csapp.cs.cmu.edu/3e/students.html）有一页可打印的 x86-64 gdb 命令速查，还链接了 Norm Matloff 教授的 GDB 教程。

几条使用建议：想让炸弹别每次输错就炸，先学会设断点；在线文档在 gdb 里输 help，或在 Unix 提示符下 man gdb、info gdb；也有人喜欢在 emacs 的 gdb-mode 里跑。今年不一样——§7 直接给你整理好了一份速查表。

objdump -t —— 符号表

打印炸弹的符号表（symbol table）：炸弹里所有函数与全局变量的名字、它调用的所有函数的名字，以及它们的地址。

看看函数名就能学到东西！比如你会发现一个叫 explode_bomb 的函数——那里正是设断点、防止炸弹真爆的好地方。

objdump -d —— 反汇编

反汇编炸弹的全部代码（也可以只看单个函数）。读懂汇编代码，炸弹的工作原理就摆在眼前了。

不过 objdump -d 不会告诉你全部：对系统级函数的调用显示得很隐晦。例如对 sscanf 的调用可能显示成：

8048c36:  e8 99 fc ff ff   call   80488d4 <_init+0x1a0>

要确认这真的是 sscanf，你得在 gdb 里反汇编。

strings —— 可打印字符串

列出炸弹里所有可打印的字符串。隐藏关卡要是想留线索，多半也藏在这里面（§9）。

找不到想用的工具？
apropos、man 和 info 是你的朋友。特别地，man ascii 可能派上用场；info gas 会告诉你关于 GNU 汇编器的一切——比你想要的还多。卡住了，随时找助教。

7. gdb 命令速查原第 5–6 页

开拆之前，建议先读 CS:APP 教材 3.10.2 节里针对具体 gdb 命令的详细介绍。

通常，启动 gdb bomb 之后，先用 layout asm 和 layout regs 打开两个视图，分析起来更顺手；要关闭 layout 视图，先按 Ctrl + x，再按 a。

p 和 x 的分工务必分清：p 打印表达式的值；x 主要用来查看内存内容。常见用法见表 2。

7.1 x 命令的后缀怎么读

这些命令斜杠后的后缀（如 2x、2d、s、g、20c）规定了查看内存的方式与数量。具体来说：

  • 第一个数字（如 2、20）指定要查看的单位个数；
  • 字母 c/d/x 表示按字符 / 十进制 / 十六进制格式查看；
  • 字母 s 表示按 C 风格字符串查看；
  • 字母 b/h/w/g 表示以字节 / 半字（2 字节）/ 字（4 字节）/ 巨字（8 字节）为单位。
单位会「粘住」
用过 x/b、x/h、x/w、x/g 之后，单位会一直保持，直到你再次用这类命令去改变它。
交互：x 命令后缀解析器——把一条 x 命令拆开讲明白

8. 用 .gdbinit 自动化原第 6–7 页

每次开 gdb 都重敲一遍断点？把配置写进 .gdbinit，一劳永逸。

.gdbinit 文件是 gdb 的一个强大功能：它允许用户在启动时自动加载默认配置，省去反复手动敲命令的过程，能显著简化调试。

8.1 配置步骤

在当前目录创建 .gdbinit
touch .gdbinit
创建配置目录
mkdir -p ~/.config/gdb
允许 gdb 从根目录预加载文件
mkdir -p ~/.config/gdb
echo "set auto-load safe-path /" >> ~/.config/gdb/gdbinit

接着打开 .gdbinit，加入以下配置：

# Set default input file, avoiding manual input each time
set args psol.txt

# Set breakpoints at each phase function to monitor execution
b phase_1
b phase_2
b phase_3
b phase_4
b phase_5
b phase_6

借助 .gdbinit，断点与其它命令都能自动布好，调试体验更高效、更不易出错。

8.2 给断点编程

.gdbinit 不只能简化初始化，还能做断点脚本：程序命中指定断点时自动执行一串动作，让调试工作流更顺畅。例如：

b phase_1
command
p $rsp   # Print the value of the stack pointer
end

这段脚本会在命中 phase_1 断点时自动打印栈指针的值。（也许你还能想到其它有用的脚本，awa。）

交互：.gdbinit 生成器——勾选要写入的配置，直接复制走
