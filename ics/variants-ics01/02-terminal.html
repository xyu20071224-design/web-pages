课程导览与起源原第 1–6 页

《计算机系统导论》第 1 讲：课程概述。这一讲不讲技术细节，而是回答三个问题 —— 这门课从哪来、要学什么、怎么学。

本讲提纲

一句话核心

这门课从程序员视角看计算机系统：不满足于「程序能跑」，而是搞清楚它在机器上怎么跑、为什么快、为什么错。

它和其他课的关系

为后续的编译、网络、操作系统、计算机体系结构等课程打地基 —— 这门课建立的是「整体框架」。

0.1 课程的由来

创立
  • 由卡耐基梅隆大学（CMU）计算机科学学院创立。
  • 全球超过 180 所大学采用了该课程教材、设立了相同或类似的课程。
  • 特点：注重实践（程序员视角），强调对系统的理解。
发展
  • 2012 年，北大信息科学技术学院与 CMU 计算机科学学院联合对该课程进行升级，并正式引入国内。

本课程采用「大班讲授 + 小班研讨」并行的方式：每周两次大班授课，每周一次小班研讨。

本课程关注的问题与目标

关注：计算机抽象概念与实际计算机系统之间的差异，以及抽象概念在真实系统上的实现方式。

目标：建立计算机系统的整体知识框架；训练良好的编程习惯（性能、可移植性、健壮性）；为后续专业课奠定基础。

问题 3：内存对程序性能至关重要

Memory Matters — Random Access Memory Is an Unphysical Abstraction

  • 内存是有限的：必须合理分配与管理；很多程序受限于内存。
  • 内存引用错误尤为严重：错误的危害因时间、空间而异（可能立刻崩溃，也可能悄悄改坏数据）。
  • 内存性能并不是始终如一的：高速缓存与虚拟内存极大影响性能 —— 也可以依此对程序调优。
交互：越界写入会改坏什么？（点数组下标 i 看结果）

问题 4：算法性能分析结果 ≠ 实际程序性能

There's more to performance than asymptotic complexity

  • 代码写得好坏，可能导致程序性能的数量级差别。
  • 程序性能优化有多个层面：算法、数据表达、过程、循环。
  • 只有理解了系统实现才能做到有效优化 —— 要了解编译与执行过程中的细节，例如内存访问模式。
交互：同一段拷贝，换个循环顺序差 19 倍

问题 5：计算机网络环境下的新问题

Computers do more than execute programs

输入输出无处不在
  • 程序执行前需要输入数据、执行后需要输出结果；
  • 网络环境下数据的来源可能是本地磁盘，也可能是网络中的其它计算机（例如把数据上传到服务器，借服务器的算力做仿真）；
  • I/O 系统对程序的稳定性与性能至关重要 —— 缺少 I/O 异常处理能力就会出错。
正确性与并发
  • 如何保证从别的机器获得数据时的正确性 / 可靠性；
  • 不同计算机引起的并发操作会相互干扰：如果计算机之间没有协作（并发控制），会导致数据库中「更新丢失」错误。
