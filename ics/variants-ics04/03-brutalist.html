1. Intel x86 的演进原第 3–9 页

x86 统治了笔记本、台式机与服务器市场。它的设计是演化出来的，不是重新设计出来的 —— 这解释了很多「古怪」之处。

1.1 演化式设计带来的特点

  • 向后兼容到 1978 年的 8086：新处理器必须能跑旧代码。
  • 功能不断累加，如今手册已有 3 卷、约 5000 页。
  • 属于 CISC（复杂指令集计算机）：指令多、格式杂。
  • 但 Linux 程序实际只会遇到其中很小的一个子集。
  • 按 RISC 路线做本来很难达到同等性能 —— 但 Intel 做到了（速度上；低功耗方面则未必）。

1.2 里程碑

1.3 64 位的往事：为什么标准是 AMD 定的

时间事件
2001Intel 尝试激进转向 IA64（Itanium）：全新架构，只能以遗留方式跑 IA32 代码，性能令人失望
2003AMD 给出演化式方案：x86-64（后来被称为 AMD64）
—Intel 碍于面子继续押注 IA64（承认错误、或承认 AMD 更好，都很难）
2004Intel 宣布 EM64T（Extended Memory 64-bit Technology）扩展 —— 与 x86-64 几乎一模一样
关于 AMD 的补充
历史上 AMD 一直跟在 Intel 后面：稍慢一点、便宜很多。后来它从 DEC 等公司挖来顶尖电路设计师，做出 Opteron 与 x86-64，一度反超；再后来 Intel 缓过神来，1995–2011 年一直是全球第一半导体厂，2018 年掉到第二（第一是三星），2019 年又夺回第一。AMD 一度落后、依赖外部代工（GlobalFoundries），到 2019 年前后的 Ryzen 才重新有竞争力。

2. 程序员可见状态与编译流水线原第 13–17 页

写机器级代码时，你脑子里要有一台「简化版的机器」：它只有 PC、寄存器、条件码和内存。

2.1 程序员可见状态

CPU 侧
  • PC（程序计数器）：下一条指令的地址。x86-64 里叫 %rip。
  • 寄存器堆：被频繁使用的程序数据。
  • 条件码：保存最近一次算术或逻辑运算的状态信息，用于条件分支。
内存侧
  • 按字节寻址的数组。
  • 存放代码与用户数据。
  • 还有一块栈，用来支持过程调用。

2.2 从 C 到可执行文件

C 程序  p1.c p2.c
  ↓ 编译器 gcc -Og -S
汇编程序  p1.s p2.s
  ↓ 汇编器 gcc / as
目标程序  p1.o p2.o  （+ 静态库 .a）
  ↓ 链接器 gcc / ld
可执行程序  p

编译命令：gcc -Og p1.c p2.c -o p —— -Og 表示使用「基本优化」（较新版本 GCC 新增的选项），-o p 指定输出文件名。

2.3 一个完整的例子：sum.c

C 代码
long plus(long x, long y);

void sumstore(long x, long y,
             long *dest)
{
    long t = plus(x, y);
    *dest = t;
}
编译器生成的 x86-64 汇编
sumstore:
    pushq  %rbx
    movq   %rdx, %rbx
    call    plus
    movq   %rax, (%rbx)
    popq   %rbx
    ret

用 gcc -Og -S sum.c 得到文件 sum.s。

警告：不要照抄书上的汇编
不同的 gcc 版本、不同的编译器设置会生成很不一样的结果（Andrew Linux、Mac OS-X 都不同）。必须在你自己的机器上重新生成。

3. 机器码与反汇编原第 18–24 页

汇编是给人看的文本，机器码才是处理器执行的字节。两者一一对应 —— 这正是反汇编能工作的原因。

3.1 汇编的特征

数据类型
  • 「整数」数据：1、2、4、8 字节 —— 既可表示数据值，也可表示地址（无类型指针）。
  • 浮点数据 4、8、10 字节；SIMD 向量数据 8、16、32、64 字节。
  • 代码：编码了一串指令的字节序列。
  • 没有数组、结构体这类聚合类型 —— 内存里只是连续分配的字节。
操作
  • 在内存与寄存器之间传送数据：从内存 load 到寄存器、把寄存器 store 到内存。
  • 对寄存器或内存数据做算术运算。
  • 控制转移：过程的无条件跳转、条件分支、间接跳转。

3.2 目标代码：sumstore 的 14 个字节

交互：机器码字节查看器（点字节或点指令）
汇编器 assembler
  • 把 .s 翻译成 .o；
  • 给出每条指令的二进制编码；
  • 是近乎完整的可执行代码映像；
  • 但缺少不同文件之间的链接信息。
链接器 linker
  • 解析文件之间的引用；
  • 与静态运行库合并（如 malloc、printf 的代码）；
  • 有些库是动态链接的；
  • 链接发生在程序开始执行时（动态链接）。

4. 寄存器与操作数原第 26–29 页

x86-64 有 16 个整数寄存器。mov 是使用最频繁的指令，它的操作数有三种类型。

4.1 16 个整数寄存器

4.2 寄存器名字的来历

这些名字来自它们在 IA32 时代的用途（现在大多已过时）：

64 位32 位16 位高/低 8 位原意
%rax%eax%ax%ah / %alaccumulate（累加器）
%rcx%ecx%cx%ch / %clcounter（计数器）
%rdx%edx%dx%dh / %dldata（数据）
%rbx%ebx%bx%bh / %blbase（基址）
%rsi%esi%si—source index（源变址）
%rdi%edi%di—destination index（目的变址）
%rsp%esp%sp—stack pointer（栈指针）
%rbp%ebp%bp—base pointer（基址指针）
%r8–%r15%r8d–%r15d%r8w–%r15w%r8b–%r15b64 位新增，没有历史包袱

可以只引用低 4 字节（也能只引用低 1、2 字节）。注意 %r8–%r15 的 32 位形式是加 d 后缀（%r8d），不是 %e8。

4.3 mov：三种操作数

movq  Source, Dest   （AT&T 语法：源在前、目的在后）
① 立即数 Immediate

常量整数，写作 $0x400、$-533 —— 像 C 常量，但要加前缀 $；编码用 1、2 或 4 字节。

② 寄存器 Register

16 个整数寄存器之一，如 %rax、%r13。但 %rsp 被保留作特殊用途；其它寄存器在某些指令里也有专门用途。

③ 内存 Memory

由寄存器给出地址的连续 8 字节内存，最简单的写法是 (%rax)。还有各种其它「寻址模式」。

最容易踩的坑：参数顺序
AT&T 语法是 movq Source, Dest，而 Intel 官方文档写的是 mov Dest, Source —— 顺序正好相反。我们全程使用 AT&T 语法。

5. 内存寻址模式原第 30–40 页

内存操作数怎么写，是这一讲最实用的部分 —— C 里的数组、指针、结构体访问，全都落在这几种寻址模式上。

5.1 两种最简单的形式

Normal  (R)

Mem[Reg[R]]

  • 寄存器 R 直接给出内存地址；
  • 这就是 C 里的指针解引用。
  • movq (%rcx),%rax
Displacement  D(R)

Mem[Reg[R] + D]

  • 寄存器 R 给出内存区域的起点；
  • 常量偏移 D 给出位移。
  • movq 8(%rbp),%rdx

5.2 完整形式 D(Rb, Ri, S)

D(Rb, Ri, S)  =  Mem[Reg[Rb] + S × Reg[Ri] + D]
字段取值说明
D常量位移，1 / 2 / 4 字节displacement
Rb基址寄存器：16 个整数寄存器中任意一个base
Ri变址寄存器：任意一个，但不能是 %rspindex
S比例因子：1 / 2 / 4 / 8scale
为什么 S 只能是 1、2、4、8？
因为数据类型的宽度就是 1、2、4、8 字节 —— 这个比例因子正是为了访问「数组元素」而设计的：D(Rb, Ri, S) 恰好对应 *(base + index * sizeof(elem) + offset)。

几个特例（其它字段可以省略）：

(Rb,Ri)    → Mem[Reg[Rb]+Reg[Ri]]
D(Rb,Ri)  → Mem[Reg[Rb]+Reg[Ri]+D]
(Rb,Ri,S) → Mem[Reg[Rb]+S*Reg[Ri]]

5.4 交互：swap 逐步执行

课件用连续 5 页演示了 swap 的每一步怎么改内存和寄存器。下面把它做成可单步执行的模拟器：

void swap(long *xp, long *yp) {
    long t0 = *xp;  # movq (%rdi), %rax
    long t1 = *yp;  # movq (%rsi), %rdx
    *xp = t1;       # movq %rdx, (%rdi)
    *yp = t0;       # movq %rax, (%rsi)
}
交互：单步执行（寄存器 %rdi = xp，%rsi = yp）
这个例子真正想说明什么
函数参数 xp、yp 是指针（地址），分别放在 %rdi、%rsi 里； (%rdi) 这种写法就是「去那个地址取值」。所以 4 条 mov 恰好完成了 C 的四行赋值 —— 没有任何一行是多余的。

6. 算术与逻辑运算原第 42–44 页

只有两类算术指令：带两个操作数的，和带一个操作数的。

6.1 leaq：地址计算指令

leaq  Src, Dst   把 Src 的地址写进 Dst（Src 是寻址模式表达式）

两个用途：

  1. 计算地址而不用访问内存 —— 例如 p = &x[i]; 的翻译。
  2. 计算形如 x + k*y 的算术表达式，其中 k ∈ {1, 2, 4, 8}。它不访问内存，所以常被编译器当「廉价的三操作数加法」用。
课件例子：乘以 12
long m12(long x) { return x*12; }

leaq (%rdi,%rdi,2), %rax  # t ← x + x*2 = 3x
salq $2, %rax            # return t << 2 = 12x

编译器用「一次 leaq + 一次左移」代替了乘法 —— 因为这两条指令比 imul 更快。

6.2 二元指令（两个操作数）

交互：点一条指令，看它的语义与例子
两个必须记住的点
  • 注意参数顺序！subq Src, Dest 计算的是 Dest = Dest − Src（Intel 文档写成 op Dest, Src，顺序相反）。
  • 有符号与无符号没有区分 —— 想一想为什么？（因为两者的位级运算完全相同，区别只在解释方式；需要区分时看条件码。）

7. 实战：追踪一个算术表达式原第 45–46 页

把 C 的 6 行语句和 6 条汇编指令一行行对上，是这一讲最值得反复看的一页。

7.1 C 代码与汇编对照

C 代码
long arith(long x, long y, long z)
{
  long t1 = x + y;
  long t2 = z + t1;
  long t3 = x + 4;
  long t4 = y * 48;
  long t5 = t3 + t4;
  long rval = t2 * t5;
  return rval;
}
生成的汇编
arith:
  leaq  (%rdi,%rsi), %rax  # t1
  addq  %rdx, %rax        # t2
  leaq  (%rsi,%rsi,2), %rdx # 3y
  salq  $4, %rdx           # t4
  leaq  4(%rdi,%rdx), %rcx  # t5
  imulq %rcx, %rax        # rval
  ret
三个值得注意的地方
  • t3 = x + 4 和 t5 = t3 + t4 没有单独的指令 —— 它们被合并进了 leaq 4(%rdi,%rdx), %rcx：地址计算顺便完成了加法。
  • t4 = y * 48 被拆成 leaq (%rsi,%rsi,2)（得 3y）加 salq $4（乘 16，3y × 16 = 48y）。
  • 整段代码里 imulq 只出现一次，而且只在最后算 rval 时用。

7.2 交互：逐行追踪（自己填 x、y、z）

追踪表会同时给出「C 层面的表达式值」和「对应寄存器里的值」—— 两者应当一致，这就是「编译器翻译正确」的含义。
