北京大学《计算机系统导论》第 5 讲：机器级编程 II —— 控制。上一讲看清了「数据怎么搬、怎么算」，这一讲看清「程序怎么决定下一步走哪」。

本讲提纲
  1. 条件码（condition codes）
  2. 条件分支与条件传送
  3. 循环：do-while / while / for
  4. switch 与跳转表
一句话核心

CPU 里没有 if、没有 while。C 语言的全部控制结构，在机器层只归结为三种手段：条件跳转、条件传送、间接跳转（跳转表）。

和上一讲的衔接

第 4 讲讲的是「mov 和算术」，那些指令会顺手改掉一组隐藏的状态位。这一讲就是拿这些位做判断 —— 控制流的全部秘密都在这里。

1. 回顾：操作数、LEA 与指令后缀原第 2–8 页

这一讲开头用 7 页复习第 4 讲的内容。其中寻址模式和 lea 是本节的落点 —— 后面讲控制流时会不断用到它们。

1.1 程序员可见状态：ISA 的视角原第 2 页

课件把处理器暴露给程序员的接口画成一张图：左边是 CPU，右边是内存。CPU 里有三样东西 —— 寄存器文件（register file，存高度频繁使用的程序数据）、程序计数器 PC（在 x86-64 里叫 %rip，存下一条指令的地址）、以及条件码（condition codes，存最近一次运算的状态信息）。内存则是按字节寻址的数组，同时装着代码和用户数据。

这一讲的主角是右下角那个不起眼的小方块：条件码。课件明确写出它的用途 —— 「Used for conditional branching」，专门服务于条件分支。

1.2 两操作数指令表原第 4 页

上一讲的核心表格，这里原样列出，因为这一讲的每条控制流都建立在它们之上：

格式计算备注
movq Src, DestDest = SrcSrc 可以是立即数 $const
leaq Src, DestDest = &Src把 Src 算成地址，不访问内存
addq Src, DestDest = Dest + Src
subq Src, DestDest = Dest − Src
imulq Src, DestDest = Dest × Src有符号乘法
salq Src, DestDest = Dest << Src也叫 shlq
sarq Src, DestDest = Dest >> Src算术右移（补符号位）
shrq Src, DestDest = Dest >> Src逻辑右移（补 0）
xorq Src, DestDest = Dest ^ Src异或

orq Src, DestDest = Dest | Src或

注意最后这些「备注」栏背后的一句话：除了 leaq，其余每一条都会改条件码。这在第 2 节会变成一条硬规则。

1.3 寻址模式：最一般形式原第 5 页

D(Rb, Ri, S)  →  Mem[Reg[Rb] + S × Reg[Ri] + D]
  • D：常数「位移」（displacement），1、2 或 4 字节
  • Rb：基址寄存器（base register），16 个整数寄存器里任意一个
  • Ri：变址寄存器（index register），任意一个，除了 %rsp
  • S：比例因子（scale），只能是 1、2、4、8

省略参数的几种特例：

写法含义
(Rb, Ri)Mem[Reg[Rb] + Reg[Ri]]
D(Rb, Ri)Mem[Reg[Rb] + Reg[Ri] + D]
(Rb, Ri, S)Mem[Reg[Rb] + S × Reg[Ri]]

1.4 内存操作数 vs. LEA原第 6–7 页

同一种寻址写法，出现在不同指令里含义完全不同。课件用两组对照来说明：

汇编C 等价访问内存吗
mov 6(%rbx,%rdi,8), %axax = *(rbx + rdi*8 + 6)是（读）
add 6(%rbx,%rdi,8), %axax += *(rbx + rdi*8 + 6)是（读）
xor %ax, 6(%rbx,%rdi,8)*(rbx + rdi*8 + 6) ^= ax是（读 + 写）
lea 6(%rbx,%rdi,8), %raxrax = rbx + rdi*8 + 6否 —— 只算地址

lea 是唯一的例外：它只做地址算术，不碰内存。课件给了它的两种用法 ——

  • CPU 设计者的本意：算一个指向对象的指针。例如把数组里的某一个元素（而不是整个数组）传给另一个函数：lea (%rbx,%rdi,8), %rax ⇒ rax = &rbx[rdi]
  • 编译器作者的爱用姿势：拿它做普通算术。它一条指令就能算复杂表达式，是 x86 里仅有的三种三操作数指令之一，而且不碰条件码：lea (%rbx,%rbx,2), %rax ⇒ rax = rbx*3

1.5 指令后缀：可以写，也可以不写原第 8 页

大多数 x86 指令带不带后缀都行 —— imul %rcx, %rax 和 imulq %rcx, %rax 没有任何区别。后缀只是标明操作数大小：

后缀C 类型位宽
bbyte8
wshort word16
lint（long word）32
qlong（quad word）64
谁写后缀、谁不写

  • 反汇编输出（objdump -d、gdb 的 disas）通常省略后缀
  • Intel 的手册永远省略后缀
所以看汇编时要注意它的来源 —— 这是后面几节会反复出现的细节。

2. 条件码：隐式设置原第 13–18、22 页

这是整讲的基石。CPU 里藏着 4 个只有 1 位的寄存器，记录「上一次运算的结果长什么样」。后面所有的 if、while、switch 都只是在读这 4 个位。

2.1 处理器状态（x86-64，部分）原第 13 页

课件把「正在执行的程序」需要记住的信息分成四类：

类别存在哪
临时数据寄存器文件：%rax … %r15
运行时栈的位置%rsp（当前栈顶）
当前代码控制点的位置%rip 指令指针（instruction pointer）
最近一次测试的状态条件码：CF、ZF、SF、OF

2.2 四个标志位原第 14 页

它们都是单比特寄存器，成对地服务于有符号与无符号两个世界：

标志名称谁在用它
CFCarry Flag（进位标志）无符号运算
ZFZero Flag（零标志）两者共用
SFSign Flag（符号标志）有符号运算
OFOverflow Flag（溢出标志）有符号运算

课件用一个具体例子给出全部规则：对 addq Src, Dest，等价于计算 t = a + b，然后 ——

标志何时置 1说人话
CF从最高位进位 / 借位出来时无符号溢出
ZFt == 0结果正好是零
SFt < 0（按有符号解释）结果的最高位是 1
OF补码（有符号）溢出：
(a>0 && b>0 && t<0) || (a<0 && b<0 && t>=0)		两个同号数加出了反号的数
最容易记错的一条：leaq 不设置条件码
课件特意强调：「Not set by leaq instruction」。因为 lea 是拿来做地址算术的，如果它改了标志位，夹在 cmp 和 jle 中间的 lea 就会把比较结果冲掉。这正是编译器喜欢用 lea 做算术的原因之一。
实测补充：imulq 不定义 ZF / SF
课件 p14 把 addq 的规则讲全了，但并没有说「所有算术指令都这样」。x86 手册对两操作数 imul 另有规定： 只有 CF 与 OF 有定义（用来表示乘积有没有超出 64 位），SF、ZF、AF、PF 都是未定义值。
本条不是照抄手册 —— 本页在真实 x86-64 处理器上实测过：让 imulq 的乘积等于 0，ZF 仍然是 0（同样条件下 addq 的 ZF 是 1）；让乘积为负数，SF 仍然是 0。 可见这两个位压根不是由结果算出来的。所以在这个模拟器里选中 imulq 时，ZF 与 SF 会显示为「未定义」，而不是给一个看着像对的数。

3. 条件码：显式设置（cmp / test）原第 19–20 页

算术指令是「顺手」改标志位。但做比较时我们并不想真的改掉哪个寄存器的值 —— 于是有了两条只置标志位、不写结果的指令。

3.1 cmpq：做减法但不留结果原第 19 页

cmpq Src2, Src1   ⟺   像算 a − b 一样置标志位，但不写回目的操作数

课件给的规则（cmpq b, a，即计算 a − b）：

标志条件用途
CF从最高位有进位出来无符号比较
ZFa == b相等
SF(a − b) < 0（按有符号解释）有符号
OF(a>0 && b<0 && (a−b)<0) || (a<0 && b>0 && (a−b)>0)有符号溢出
注意操作数顺序：CF 是「借位」，也就是 a < b（无符号）
AT&T 语法的 cmpq b, a 是 a 减 b。CF = 1 意味着减法需要借位，也就是无符号意义下 a < b。很多人在这一处把比较方向记反。

3.2 testq：做与运算但不留结果原第 20 页

testq Src2, Src1   ⟺   像算 a & b 一样置标志位，但不写回目的操作数

规则很简单，而且非常常用：ZF 在 a & b == 0 时置 1；SF 在 a & b < 0 时置 1。课件提醒：让其中一个操作数当掩码（mask）特别有用。最常见的一行汇编是 ——

testq %rax, %rax  —— 自己和自己与，唯一目的是判断 %rax 是不是 0、是不是负数
交互：cmp / test 追踪器
为什么比较要单独做成指令？
如果写成 subq b, a，a 的值就被破坏了。而 cmp / test 只留下「结论」，不动任何数据 —— 这使得「比较」与「分支」可以分开，中间还能插入别的指令（只要那些指令也不改标志位，比如 lea）。

4. 读取条件码：setX 与 movzbl原第 21、23–25、34–35 页

标志位算出来了，怎么把它变成一个能存进内存、能返回给调用者的值？答案是一组 setX 指令 —— 它们把标志位的「组合」写成字节 0 或 1。

4.1 setX 指令表原第 21 页

每条 setX 都把目的寄存器的低字节写成 0 或 1，依据是指定的标志位组合。它不改动其余 7 个字节。

SetX条件含义

setne~ZFNot Equal / Not Zero
setsSFNegative
setns~SFNonnegative
setg~(SF^OF) & ~ZFGreater（有符号）
setge~(SF^OF)Greater or Equal（有符号）
setl(SF^OF)Less（有符号）

4.2 为什么后面总跟着一条 movzbl原第 23–25 页

setX 只写一个字节，而且不改动其余字节 —— 这带来一个问题：高位残留的垃圾会让返回值出错。

看课件的 gt 函数：int gt(long x, long y) { return x > y; }。它被编译成：

cmpq %rsi, %rdi   # 比较 x : y
setg %al         # 大于时置 1，只写这一个字节
movzbl %al, %eax # 把 %rax 剩下的部分清零
ret

寄存器使用约定：%rdi 存参数 x，%rsi 存参数 y，%rax 存返回值。%al 是 %rax 的低 8 位。x86-64 里每个整数寄存器都能切出低字节：%rax→%al、%rbx→%bl、%rcx→%cl、%rdx→%dl、%rsi→%sil、%rdi→%dil、%rsp→%spl、%rbp→%bpl，以及 %r8→%r8b … %r15→%r15b。

movzbl 干了两件事
  1. 把 %al 的值零扩展到 %eax，%rax 剩下 56 位因此全部被冲干净。
  2. 它是一条 32 位指令，而 x86-64 规定：32 位指令会把目的寄存器的高 32 位自动清零。
两件事合起来，%rax 就是干净的 0 或 1 了。

5. 条件跳转与 if-else原第 10–12、27–30 页

有了条件码，控制流就只剩下一个问题：「这个条件成立，跳还是不跳？」。这一节看 C 的 if-else 如何被拆成一串带条件的 goto。

5.1 控制流就是 goto原第 10–12 页

课件用一个最小的例子：void decision(int x) { if (x) { op1(); } else { op2(); } }。它的汇编是：

decision:
  subq  $8, %rsp      # 按 ABI 对齐栈
  testl %edi, %edi     # 判断 x 是否为 0
  je    .L2           # x == 0 → 跳到 else 分支
  call  op1
  jmp   .L1           # 做完 then 就跳过 else
.L2:
  call  op2
.L1:
  addq  $8, %rsp
  ret

5.3 第一个完整例子：absdiff原第 28–29 页

目标是这个函数：

long absdiff(long x, long y) {
  long result;
  if (x > y) result = x-y;
  else       result = y-x;
  return result;
}

用 gcc –Og -S –fno-if-conversion 编译（-fno-if-conversion 是为了强迫编译器用分支，否则它会改用条件传送，见下一节）：

absdiff:                   # x 在 %rdi，y 在 %rsi
  cmpq  %rsi, %rdi     # 比较 x : y
  jle   .L4              # x <= y → 去 else 分支
  movq  %rdi, %rax
  subq  %rsi, %rax     # result = x - y
  ret
.L4:                     # x <= y
  movq  %rsi, %rax
  subq  %rdi, %rax     # result = y - x
  ret

课件随后把它改写成「goto 版」，这是理解一切控制流翻译的钥匙 —— if 只是在「条件成立时跳过一段代码」：

long absdiff_j(long x, long y) {
  long result;
  int ntest = x <= y;     // 把条件取反
  if (ntest) goto Else;
  result = x-y;
  goto Done;
Else:
  result = y-x;
Done:
  return result;
}
注意 ntest = x <= y 这一步
汇编里的跳转是「不满足条件时才跳走」（jle .L4 跳到 else）。而 C 的 if (x > y) 是「满足条件时执行 then」。两者的条件正好相反，所以翻译时要先把测试取反。这是手写 goto 版时最容易搞错的一步。
交互：absdiff 三种写法并排跑

5.4 一般条件表达式的翻译原第 30 页

课件把这个模式提炼成通用公式。对 val = Test ? Then_Expr : Else_Expr;，分支翻译法是：

ntest = !Test;       // 取反
if (ntest) goto Else;
val = Then_Expr;
goto Done;
Else:
  val = Else_Expr;
Done:
  . . .

核心思想只有一句：为 then 和 else 各生成一段独立代码区，然后选择执行其中一个。例：val = x>y ? x-y : y-x; 就是前面那个 absdiff。

6. 条件传送：不跳转的分支原第 31–33 页

CPU 的流水线最怕跳转。于是 x86 提供了一类不跳转也能实现条件的指令 —— 但它的代价是「两条路都要算」，这个代价决定了它能用在哪些场合。

6.1 cmov 指令原第 31 页

条件传送（conditional move）指令实现的是 if (Test) Dest ← Src。几个关键事实：

  • 1995 年之后的 x86 处理器才支持
  • GCC 会尽量使用它们 —— 但只在确认安全时
  • 为什么想要用它？分支会严重打断流水线里的指令流（branches are very disruptive to instruction flow through pipelines）；条件传送不需要控制转移

把条件表达式改写成条件传送时，C 代码长这样：

result = Then_Expr;
eval   = Else_Expr;      // 两条路都先算出来
nt = !Test;
if (nt) result = eval;  // 再挑一个
return result;
关键差异：Then_Expr 和 Else_Expr 都会被求值
分支版本只算一条路，条件传送版本两条路都算。这句话是所有限制的根源 —— 下一小节的三类「坏例子」全是从这里长出来的。

6.2 同一个 absdiff 的条件传送版本原第 32 页

absdiff:                 # x 在 %rdi，y 在 %rsi
  movq  %rdi, %rax     # x
  subq  %rsi, %rax     # result = x - y  （先算 then）
  movq  %rsi, %rdx
  subq  %rdi, %rdx     # eval   = y - x  （再算 else）
  cmpq  %rsi, %rdi     # 比较 x : y
  cmovle %rdx, %rax    # 若 x <= y，result = eval
  ret

对比 5.3 的分支版本：指令条数变多了，但一次跳转都没有。这就是编译器愿意做的交易。

6.3 什么时候不能用条件传送原第 33 页

课件列出三类「坏例子」，各自的原因完全不同 ——

情形代码问题后果
昂贵计算val = Test(x) ? Hard1(x) : Hard2(x);两个值都会被算出来性能变差（Bad Performance）
危险计算val = p ? *p : 0;两个值都会被算出来不安全（Unsafe）：p 为空时也会解引用
有副作用val = x > 0 ? x*=7 : x+=3;两个值都会被算出来非法（Illegal）：x 被改了两次

第二、三类的共性：表达式必须无副作用（side-effect free）才谈得上「两条路都算」。

7. 循环：do-while、while、for原第 37–47 页

C 有三种循环写法，但机器层只有一种：往回跳的 goto。这一节看编译器如何把三种循环统一成同一个形状。

7.1 例子：popcount（数 1 的个数）原第 37 页

贯穿本节的是同一个函数 —— 数出参数 x 里有几个二进制 1：

long pcount_do(unsigned long x) {
  long result = 0;
  do {
    result += x & 0x1;   // 取最低位累加
    x >>= 1;           // 右移一位
  } while (x);
  return result;
}

课件顺带提了一句：x86 是 CISC，本身就有 popcount 指令（一条指令数完所有 1）—— 但为了讲清楚控制流，这里仍然手动循环。

7.2 三种 goto 形式原第 38、40、42 页

课件给出两张通用翻译模板，加上原本的 do-while，一共三种形状：

形式何时用结构特征
do-while
（循环体在前）		do {...} while(Test) 的直接翻译标签在循环体开头，条件判断在末尾：先做事，再决定要不要回去
jump-to-middle
（跳到中间）		-Og 用开头一条 goto test 直接跳到条件判断处
guarded-do
（do-while 转换）		-O1 用先把条件取反挡在入口（if (!Test) goto done;），循环体后面再判一次

三种形式对应到 popcount_while 上：

do-while
result = 0;
loop:
  result += x & 0x1;
  x >>= 1;
  if (x) goto loop;
return result;
jump-to-middle
result = 0;
goto test;
loop:
  result += x & 0x1;
  x >>= 1;
test:
  if (x) goto loop;
return result;
guarded-do
result = 0;
if (!x) goto done;
loop:
  result += x & 0x1;
  x >>= 1;
  if (x) goto loop;
done:
return result;
课件在这里留了一个问题
guarded-do 相比 jump-to-middle 「移除了跳到中间」。课件追问：「When is this good or bad?」—— 想想看：少了入口处那次无条件跳转，代价是条件被写了两遍（入口一次、末尾一次），而且当循环一次都不执行时，两次判断是「重复劳动」。

7.4 对应的汇编原第 39 页

课件给出 do-while 版编译后的结果 —— 注意它长得和 goto 版一一对应：

  movl  $0, %eax      # result = 0
.L2:                    # loop:
  movq  %rdi, %rdx
  andl  $1, %edx      # t = x & 0x1
  addq  %rdx, %rax     # result += t
  shrq  %rdi           # x >>= 1（只写一个操作数 = 移 1 位）
  jne   .L2            # if (x) goto loop
  rep; ret

shrq %rdi 只写一个操作数，是「右移 1 位」的简写；jne .L2 复用 shrq 置好的 ZF —— 若移位后 x 变成 0，ZF 就是 1，jne 不跳，循环结束。省掉了一条 test。rep; ret 是编译器为老 AMD 处理器加的前缀。

7.5 for 循环原第 44–47 页

for (Init; Test; Update) Body 的通用形式包含四块：Init 只做一次，然后反复执行 Test → Body → Update。课件给的例子：

#define WSIZE 8*sizeof(int)             // 32
long pcount_for(unsigned long x) {
  size_t i;
  long result = 0;
  for (i = 0; i < WSIZE; i++) {
    unsigned bit = (x >> i) & 0x1;
    result += bit;
  }
  return result;
}

for → while 的转换最直白：Init 提到循环前，Update 挂到循环体末尾。

Init;                 // i = 0;
while (Test) {      // while (i < WSIZE)
  Body
  Update;          // i++;
}

再往下变成 do-while 时，Update 会跑到 if (Test) 之前（因为 do-while 的条件在末尾，而末尾同时也是下一轮的「更新点」）：

  i = 0;                    # Init
  if (!(i < WSIZE))      # !Test
    goto done;            // 课件问：这里的初始测试什么时候能被优化掉？
loop:
  {                       # Body
    unsigned bit = (x >> i) & 0x1;
    result += bit;
  }
  i++;                     # Update
  if (i < WSIZE)         # Test
    goto loop;
done:
  return result;
课件的问题：初始测试什么时候能优化掉？
当编译器能证明循环至少会执行一次时 —— 这里 i = 0 且 WSIZE = 32 > 0 都是编译期常量，初始测试 i < WSIZE 恒真，于是可以直接删掉。这类「常量传播 + 死代码消除」是优化的常规动作。
交互：for → while → do-while 三层对照

8. switch 与跳转表原第 49–58、62–64 页

一串 if-else 要比较 n 次；跳转表（jump table）把这个比较过程变成一次内存查表 + 一次间接跳转。这是编译器最漂亮的优化之一。

8.1 例子：switch_eg原第 49 页

long switch_eg(long x, long y, long z) {
  long w = 1;
  switch(x) {
    case 1:           // 单个标签
      w = y*z;
      break;
    case 2:           // fall through（贯穿）
      w = y/z;
      /* Fall Through */
    case 3:
      w += z;
      break;
    case 5:           // 多个标签共用一段代码
    case 6:
      w -= z;
      break;
    default:         // 缺了 case 4
      w = 2;
  }
  return w;
}

课件点出这个例子里的三个要点：多个 case 标签（5 和 6）、贯穿的 case（2 落到 3）、缺失的 case（没有 4）。

8.2 跳转表的结构原第 50 页

跳转表是一个数组，第 i 项存放「case i 对应代码块的地址」。原来的 switch 被翻译成一句扩展 C：

goto *JTab[x];

它的形状是「三段式」：左边是 switch 形式，中间是跳转表 jtab，右边是各个代码块 Targ0 … Targn−1。查表的过程就是：用 x 当下标 → 取出地址 → 跳过去。

8.3 汇编里的设置代码原第 51–53 页

switch_eg:                 # %rdi = x，%rsi = y，%rdx = z
  movq  %rdx, %rcx         # 把 z 挪到 %rcx 备用
  cmpq  $6, %rdi           # 比较 x : 6
  ja    .L8                 # 无符号「大于」→ 走 default
  jmp   *.L4(,%rdi,8)      # goto *JTab[x]  （间接跳转）
交互：x 取哪些值会走 default？

跳转表本身放在只读数据段 .rodata 里，每一项 8 字节（一个地址）：

  .section .rodata
  .align 8              // 对齐到 8 字节边界
.L4:
  .quad .L8             # x = 0  → default
  .quad .L3             # x = 1  → w = y*z
  .quad .L5             # x = 2  → w = y/z，再贯穿
  .quad .L9             # x = 3  → w += z
  .quad .L8             # x = 4  → default（缺这个 case）
  .quad .L7             # x = 5  → w -= z
  .quad .L7             # x = 6  → w -= z（与 5 共用）

课件解释了三处细节：表的每一项占 8 字节；基地址是 .L4；跳转分直接（jmp .L8，目标写在指令里）与间接（jmp *.L4(,%rdi,8)，目标从内存取）。间接跳转必须按 8 倍缩放，因为地址是 8 字节宽 —— 所以取的地址是 .L4 + x*8。这套机制只对 0 ≤ x ≤ 6 成立，超出的值靠前面那条 ja 挡掉。

交互：跳转表生成器（改 case 集合，看表怎么变）

8.4 各个代码块原第 55–58 页

x == 1 → .L3
.L3:
  movq  %rsi, %rax   # y
  imulq %rdx, %rax   # y*z
  ret
x == 5, 6 → .L7
.L7:
  movl $1, %eax      # w = 1
  subq %rdx, %rax    # w -= z
  ret
default → .L8
.L8:
  movl $2, %eax      # 2
  ret
x == 2, 3 → .L5 / .L9 / .L6
.L5:                 # Case 2
  movq %rsi, %rax
  cqto
  idivq %rcx         # y/z
  jmp .L6            # goto merge
.L9:                 # Case 3
  movl $1, %eax      # w = 1
.L6:                 # merge:
  addq %rcx, %rax    # w += z
  ret

课件特别展示了贯穿（fall through）怎么实现：case 2 算完 y/z 后并不 ret，而是 jmp 到合并点 .L6，与 case 3 共享同一条 w += z。而 case 3 自己则要先执行 movl $1, %eax —— 因为 long w = 1 的初始化被挪进了各个分支，没走到的分支不必初始化。

交互：switch_eg 求值器（输入 x, y, z，看结果与路径）

8.5 在二进制里找出跳转表原第 62–64 页（补充材料）

反汇编 switch_eg，间接跳转的地址直接写在指令里：

00000000004005e0 <switch_eg>:
  4005e0:  48 89 d1               mov    %rdx,%rcx
  4005e3:  48 83 ff 06           cmp    $0x6,%rdi
  4005e7:  77 2b                   ja     400614 <switch_eg+0x34>
  4005e9:  ff 24 fd f0 07 40 00  jmpq   *0x4007f0(,%rdi,8)
  …

从 jmpq *0x4007f0(,%rdi,8) 就能读出跳转表的基地址是 0x4007f0。用 gdb 把内存倒出来：

% gdb switch
(gdb) x /8xg 0x4007f0
0x4007f0:  0x0000000000400614  0x00000000004005f0
0x400800:  0x00000000004005f8  0x0000000000400602
0x400810:  0x0000000000400614  0x000000000040060b
0x400820:  0x000000000040060b  0x2c646c25203d2078
(gdb)
交互：顺着间接跳转走一遍
注意第 8 项：为什么它是「乱码」
表里只有 7 个有效项（x = 0…6），第 8 项 0x2c646c25203d2078 已经越过了表的末尾，落在旁边的字符串常量上（按小端读出来的 ASCII 是 x = %ld, 的一部分）。这正说明跳转表只对 0 ≤ x ≤ 6 有效 —— 那条 cmpq $6 / ja 的边界检查不是可有可无的装饰，它是防止越界跳转的安全屏障。去掉它，x = 7 就会跳到一段数据上当作代码执行。
