把「执行一条指令」拆成取指 → 译码 → 执行 → 访存 → 写回 → 更新 PC 六个阶段之后，所有 15 条指令都能套进同一个硬件框架：指令之间只有「每个阶段算什么」不同 —— 这张差异表用 HCL 写出来，就是全部控制逻辑。

1. Y86-64 指令集与编码原第 2–5 页

课件连放四页同一张指令表不是凑数：第 2 页给全表，第 3、4、5 页分别把 cmovXX 的 7 个功能码、OPq 的 4 个功能码、jXX 的 7 个功能码「放大」给你看。造控制逻辑之前，必须先把这张表刻进脑子。

1.1 编码总则原第 2 页

每条指令的第一个字节拆成两个 4 位数：高 4 位 icode（指令码）+ 低 4 位 ifun（功能码）。其后可选地跟一个寄存器字节（高 4 位 rA、低 4 位 rB）和一个 8 字节常数字 valC（小端存放）。哪些指令带寄存器字节、哪些带常数字，一眼看表：

指令icodeifun寄存器字节常数字长度
halt / nop / ret0 / 1 / 90无无1 字节
rrmovq / cmovXX, OPq, pushq / popq2 / 6 / A / Bfn有（rA:rB）无2 字节
jXX, call7 / 8fn / 0无有（Dest）9 字节
irmovq / rmmovq / mrmovq3 / 4 / 50有（rA:rB）有（V 或 D）10 字节

寄存器用 4 位编号表示（上一讲已给出，这里作为速查）：0 %rax · 1 %rcx · 2 %rdx · 3 %rbx · 4 %rsp · 5 %rbp · 6 %rsi · 7 %rdi · 8 %r8 · 9 %r9 · A %r10 · B %r11 · C %r12 · D %r13 · E %r14 · F 不访问（RNONE）。pushq rA 和 popq rA 的第二个 4 位填 F —— 只有一个寄存器操作数，另一半空着。

交互：点击指令行，看它的字节长什么样 （fn 列的「放大页」：cmovXX → 原第 3 页，OPq → 原第 4 页，jXX → 原第 5 页）

2. 处理器构件、时钟与 HCL原第 6–8 页

造机器先认积木。课件第 6 页把构件分成两大类，第 7–8 页给出一门「迷你硬件描述语言」HCL —— 本讲后面所有灰色控制块都用它书写。

构件行为（课件原话的展开）例子

为什么这条规矩是 SEQ 的命根子
SEQ 的每个周期里，组合逻辑从「旧状态」出发，一路算出 valE、valM、新 PC…… 但这些结果悬在半空不落地，直到时钟上升沿才被统一写进 PC、CC、寄存器堆、内存。「算」是连续的，「记」是定时的 —— 第 10 节的模拟器会让你亲眼看到这两拍的区别。

2.2 硬件控制语言 HCL原第 7–8 页

HCL 是一门非常简单的硬件描述语言 —— 课件原话：它只表达硬件操作里我们想探索和修改的那一小部分。两种数据类型、两种语句：

bool a = bool-expr;   /* 布尔：a, b, c … */
int  A = int-expr;    /* 字：A, B, C … 不指定位宽（字节？32 位字？）*/

表达式按返回值分两类：布尔表达式有逻辑运算 a && b、a || b、!a，字比较 A == B、A < B……，以及集合隶属 A in { B, C, D }（等价于 A==B || A==C || A==D）；字表达式用选择表达式（case）从多个候选里挑一个：

int A = [
  a  : A;  /* 依次求值 a、b、c …… */
  b  : B;  /* 返回第一条命中的测试对应的字表达式 */
  c  : C;
];
交互：HCL 求值器 —— 拨动输入，看 case 按顺序命中哪条
HCL 的 case 不是 C 的 switch
C 的 switch 要求整数表达式、跳转表；HCL 的选择表达式按书写顺序逐条求值测试，第一条命中立即返回对应的字表达式 —— 更像一串三元运算符串起来。测试也可以是任意布尔表达式（第 6–9 节全是 icode in { …… } 这种写法）。

3. SEQ 总体结构与六个阶段原第 9–10、29 页

SEQ 是「顺序（sequential）」实现：一个时钟周期执行一整条指令，六个阶段从头走到尾。先记住六个阶段的名字和职责 —— 本讲剩下的篇幅都在回答「每个阶段具体怎么算」。

3.1 六个阶段原第 10 页

阶段做什么代表性计算
Fetch 取指从指令内存读出 PC 处的指令icode:ifun、可选 rA:rB、可选 valC、valP（下一条地址）
Decode 译码读程序寄存器valA、valB（读端口 A / B）
Execute 执行算值或算地址valE（ALU）、置/用条件码、Cnd（条件标志）
Memory 访存读或写数据内存valM
Write back 写回写程序寄存器最多两个：ALU 结果 + 内存结果
PC update更新程序计数器下一条指令的地址

4. 指令解码：一条指令的字节原第 11 页

取指阶段读到的就是一串字节。课件第 11 页把格式画成一条带「Optional」标签的字节带：指令字节 icode:ifun 必有，寄存器字节 rA:rB 与常数字 valC 看指令而定。

4.1 字节带的两种形状原第 11 页

例：5 0 rA rB D —— mrmovq D(rB), rA：1 字节 icode:ifun + 1 字节 rA:rB + 8 字节位移 D，共 10 字节
  • 指令字节：高 4 位 icode、低 4 位 ifun（第 6 节的 Split 块就干这个切分）。
  • 寄存器字节（可选）：rA 在高 4 位、rB 在低 4 位；不需要的那一半填 F（RNONE，不访问）。
  • 常数字（可选）：8 字节，小端存放 —— 低位字节在低地址。
交互：指令字节拆分器 —— 输入一串十六进制，看它怎么被切分
「Optional」由两个信号决定
拆分器右下角的 need regids 与 need valC 就是课件第 30–31 页取指硬件里的两个控制信号：前者看 icode 是否在 {rrmovq/cmovXX, OPq, pushq, popq, irmovq, rmmovq, mrmovq} 里，后者看是否在 {irmovq, rmmovq, mrmovq, jXX, call} 里。指令长度 = 1 + need_regids + 8×need_valC，valP = PC + 长度 —— 全部由硬件现算。

6. 取指逻辑原第 30–33 页

从这一节起进入灰色控制块内部。取指逻辑回答三个问题：指令内存读什么、字节怎么切、这条指令合不合法。它的全部智慧浓缩在四条 HCL 定义里。

6.1 预制块：内存、Split、Align原第 30 页

块职责
指令内存从 PC 起连读 10 字节（PC 到 PC+9，一取到底）—— 多出的字节没人用；地址无效时发出 imem_error 信号

6.2 控制信号与 HCL原第 31–33 页

灰色部分产出三个信号：Instr valid（这条指令合法吗）、Need regids（有寄存器字节吗）、Need valC（有常数字吗）。写成 HCL（课件第 32–33 页原文）：

# Determine instruction code
int icode = [
  imem_error : INOP;  /* 取不到指令 → 按 nop 处理 */
  1         : imem_icode;
];
# Determine instruction function
int ifun = [
  imem_error : FNONE;
  1         : imem_ifun;
];
bool need_regids =
  icode in { IRRMOVQ, IOPQ, IPUSHQ, IPOPQ,
             IIRMOVQ, IRMMOVQ, IMRMOVQ };
bool instr_valid = icode in
  { INOP, IHALT, IRRMOVQ, IIRMOVQ, IRMMOVQ, IMRMOVQ,
    IOPQ, IJXX, ICALL, IRET, IPUSHQ, IPOPQ };
交互：取指 HCL 求值 —— 选 icode，看每条 case 命中哪行
勘误一：第 33 页指令表里 irmovq 的 rA 格写成了 8
原课件第 33 页左上的指令表把 irmovq V, rB 一行写作 3 0 8 rB V，而同一课件第 2–5 页的全部四张表、以及 need_regids 的语义都指向 3 0 F rB V（F = RNONE，irmovq 没有源寄存器）。该格在课件里本就是高亮的「不用」格，高亮含义不受影响，但字符按 F 呈现。
勘误二：第 33 页指令表把 pushq 误写成 popq
原课件第 33 页同一张表的倒数第二行是 popq rA  A 0 rA F —— icode A 是 pushq（第 2–5 页：pushq rA  A 0 rA F；popq 是 icode B，即下一行）。本页按 pushq rA  A 0 rA F 呈现。

7. 译码与写回逻辑原第 34–36 页

寄存器堆是个「四端口」设备：两个读端口 A、B，两个写端口 E、M。端口地址（srcA / srcB / dstE / dstM）全由 icode（必要时加上 Cnd）决定 —— 课件用两条 HCL 给出其中最重要的两条。

7.1 寄存器堆与端口原第 34 页

端口方向地址信号含义
A读srcA读出 valA
B读srcB读出 valB
E写dstE写入 ALU 结果 valE
M写dstM写入内存结果 valM
  • 端口地址是寄存器 ID；填 15（0xF）表示这个端口不访问任何寄存器（RNONE）。
  • 信号 Cnd 在执行阶段算出，但它的消费方之一就在写回：cmovXX 要不要落笔，看它。

7.2 srcA：读端口 A 的地址原第 35 页

课件先把五类指令的「读 A」动作排成一列（OPq / cmovXX / rmmovq 读 R[rA]，popq / ret 读栈指针，jXX / call 干脆不读），然后一句话收拢成 HCL：

int srcA = [
  icode in { IRRMOVQ, IRMMOVQ, IOPQ, IPUSHQ  } : rA;
  icode in { IPOPQ, IRET }                    : RRSP;
  1 : RNONE;  /* 不需要寄存器 */
];

7.3 dstE：写端口 E 的地址原第 36 页

写回一侧同理（OPq 写 R[rB]、popq/call/ret 更新栈指针、rmmovq / jXX 什么都不写）：

int dstE = [
  icode in { IRRMOVQ } && Cnd : rB;  /* 条件传送：Cnd 不成立就不写 */
  icode in { IIRMOVQ, IOPQ }         : rB;
  icode in { IPUSHQ, IPOPQ, ICALL, IRET } : RRSP;
  1 : RNONE;  /* 不写任何寄存器 */
];

另外两个端口没有单独的 HCL 页，但把各指令的阶段表（第 5 节）横着一比就能归纳出来：srcB —— OPq 与 mrmovq 读 R[rB]，popq / ret / call / pushq 读 R[%rsp]，其余 RNONE；dstM —— 只有「从内存拿数据写回寄存器」的两条用得上：popq 写 rA、mrmovq 写 rA（课件第 17 页 popq 表的 R[rA] ← valM 就是 dstM 端口在工作）。

交互：译码/写回端口 —— 选指令，看四个端口各接到哪
为什么 cmovXX 要「把目的寄存器改成 0xF」
课件第 19 页的妙笔：条件不满足时不搞「跳过写回」这种新机制，而是把 dstE 改成 0xF（RNONE）—— 写回硬件照常工作，只是地址指向「不存在的寄存器」。一套写回电路服务所有指令，这就是「用同一框架」的代价与回报。

为什么 le 和 l 只差一个 ZF
「小于」的硬件定义是 SF ≠ OF：同号相减得异号结果，必是溢出捣乱，此时真实大小关系与 SF 相反。「小于等于」再加上「等于零」：l：SF^OF，le：SF^OF 或 ZF。ge / g 是它们的补。这就是 fn 编号 1–6 背后的全部数学。

9. 内存逻辑与 PC 更新原第 40–45 页

倒数两块控制逻辑：内存逻辑决定这一周期读不读、写不写、地址是谁、数据是谁，顺手给出处理器状态 Stat；PC 更新逻辑在四个候选里挑出下一个 PC。

9.1 内存逻辑的五个信号原第 40–43 页

  • Stat：这条指令的状态（正常 / 地址错 / 指令错 / 停机）；
  • Mem. read：要不要读一个 8 字节字（mrmovq / popq / ret）；
  • Mem. write：要不要写一个 8 字节字（rmmovq / pushq / call）；
  • Mem. addr：读写的地址从哪来 —— rmmovq/pushq/call/mrmovq → valE，popq/ret → valA；
  • Mem. data：写的数据从哪来 —— rmmovq / pushq 用 valA，call 用 valP（要存的「返回地址」正是下一条指令的位置）。
int mem_addr = [
  icode in { IRMMOVQ, IPUSHQ, ICALL, IMRMOVQ } : valE;
  icode in { IPOPQ, IRET }                   : valA;
  /* 其他指令不需要地址 */
];
bool mem_read = icode in { IMRMOVQ, IPOPQ, IRET };

9.3 PC 更新：四选一原第 44–45 页

int new_pc = [
  icode == ICALL      : valC;  /* call：去目的地 */
  icode == IJXX && Cnd : valC;  /* 跳转且条件成立 */
  icode == IRET       : valM;  /* ret：从栈上取回 */
  1                 : valP;  /* 默认：顺序下一条 */
];

候选一共就四个：valC（call / 命中的跳转）、valM（ret 从栈里读回的地址）、valP（顺序下一条）。注意 jXX 的「不跳」不需要专门一行 —— Cnd 为 0 时自然落进默认分支 valP。

10. SEQ 时序：时钟与模拟器原第 46–50 页

所有控制逻辑就位之后，只剩一个问题：这些块怎么协同？答案是一个时钟：状态元件（PC、CC、寄存器堆、数据内存）在时钟上升沿统一更新；组合逻辑在整个周期里持续反应。课件用五页把同一段五指令程序翻了四遍 —— 下面的模拟器把它变成可以亲手拨动的机器。

10.1 状态元件 vs 组合逻辑原第 46 页

类别成员更新时机
状态元件
（本讲开头那四样）		PC 寄存器、条件码寄存器 CC、数据内存、寄存器堆统一在时钟上升沿更新
组合逻辑 + 内存读ALU、各控制块、指令内存读、寄存器堆读、数据内存读连续 —— 输入（状态）一变就开始算新输出

于是每个周期是固定的两拍：组合逻辑从当前状态算出全部下一状态 → 时钟上升沿把下一状态写入状态元件。寄存器堆有点特别：读端口连续响应（组合），写端口在时钟沿落地（状态）。

11. 总结与测验原第 2、51 页

11.1 SEQ 总结原第 51 页

实现方法（课件原文展开）
  • 把每条指令表达成一系列简单步骤；
  • 每类指令走同一个通用流程；
  • 用寄存器、内存与预制的组合块搭出硬件；
  • 用控制逻辑把它们连起来（本讲用 HCL 写的那些 int xxx = [……]）。
局限（课件原文展开）
  • 太慢，不实用；
  • 一个周期里信号要串行穿过：指令内存 → 寄存器堆 → ALU → 数据内存；
  • 时钟必须跑得非常慢，等最长的路径稳定；
  • 硬件单元每个周期只有一小段时间真正在工作。
慢在哪，下一讲就快在哪
六个阶段其实是串联的：取指的输出喂译码，译码的输出喂执行……一个周期里整条链只服务一条指令，链上每个单元绝大部分时间在等。下一讲（PIPE）把这条链切成五段、每个单元每个周期都开工 —— 流水线。SEQ 的价值在于：它用最少的机制把「指令级语义 → 硬件状态机」这件事讲透了，后面所有的加速都是在它身上做手术。
