课程导览原第 1–2 页

北京大学《计算机系统导论》第 12 讲：存储层次结构（The Memory Hierarchy）。这一讲回答两个问题：为什么一台计算机需要一整套从小到大、从快到慢的存储设备？以及程序自身的什么性质，让这套看似「重复」的结构真的有效？答案的两半 —— 硬件侧的存储技术，软件侧的局部性 —— 在本讲各占一半篇幅，最后用「缓存」把它们缝在一起。

本讲提纲（课件第 2 页原文）
  1. 内存抽象（The memory abstraction）
  2. RAM：主存的积木
  3. 存储技术与趋势
  4. 引用局部性（Locality of reference）
  5. 存储层次中的缓存
一句话核心

从寄存器到远端服务器的每一层存储，都是下一层的缓存：更小、更快、更贵的那一层，缓存更大、更慢、更便宜的一层里的一小部分数据。之所以能这样干，是因为程序不会均匀地访问内存 —— 它总在反复用最近用过的数据和它附近的数据。这就是局部性。

这一讲在课程里的位置

第 6–8 讲把 CPU 造出来了（SEQ），但机器一条指令一个周期，慢得不能实用。原因不在 CPU，而在它要等内存。这一讲先把「内存」这一侧讲透：内存与磁盘的真实速度、容量、代价；再给出解决方案的钥匙 —— 局部性；最后给出方案本身 —— 存储层次与缓存。下一讲（缓存存储器）把这一讲的缓存模型落到真实的 cache 几何上。

1. 内存抽象：总线与读写事务原第 3–9 页

「内存是一个很大的字节数组」是给程序员看的抽象。硬件看到的是另一幅图：CPU 与内存在一条总线上对话。课件用整整七页（原第 3–9 页）把一次读和一次写各拆成三步 —— 这是理解「内存访问为什么有代价」的起点。

1.1 总线：一组并行导线原第 3 页

  • 总线（bus）是一组并行导线，传送地址、数据与控制信号；
  • 总线通常被多个设备共享；
  • 课件图里的层次是：CPU 芯片（内含寄存器堆、ALU、总线接口）→ 系统总线 → I/O 桥 → 内存总线 → 主存；I/O 桥的另一侧接 I/O 总线（USB 控制器、图形适配器、磁盘控制器，还有扩展槽）。
交互：总线结构漫游 —— 点部件看它在数据通路上干什么

1.2 读事务：三步原第 4–6 页

课件把 movq A, %rax（load）拆成三张连续页：

第 1 步 · 原第 4 页
CPU 把地址 A 放到内存总线上
此时总线上跑的是「我要 A」这个请求，数据还没出现。
第 2 步 · 原第 5 页
主存从内存总线读走 A，取出字 x，把它放回总线
这一步的耗时就是 DRAM 的访问时间（本页第 7 节会给数字）。
第 3 步 · 原第 6 页
CPU 从总线读走字 x，把它复制进寄存器 %rax
抽象的 movq A, %rax 到此完成 —— 程序员只看到一行指令。

1.3 写事务：也是三步原第 7–9 页

课件把 movq %rax, A（store）同样拆成三步，注意第 1 步的细节 —— 地址先走，主存先等着，数据随后到：

第 1 步 · 原第 7 页
CPU 把地址 A 放到总线上；主存读走它，并等待对应的数据字到达
「等待」是关键：总线协议允许地址与数据分两拍传。
第 2 步 · 原第 8 页
CPU 把数据字 y 放到总线上
y 来自 %rax（原图里寄存器堆中写着 y）。
第 3 步 · 原第 9 页
主存从总线上读走数据字 y，把它存到地址 A
写事务结束 —— 内存数组里 A 处的值变成 y。
交互：读写事务分步器 —— 切换读/写，逐步看总线上跑着什么
内存抽象的两半
程序员那一半：内存是一个很大的字节数组，每个字节有地址；movq A, %rax 里的 A 是地址，不是数据。硬件那一半：每个 load/store 都变成总线上的一次事务（transaction），地址、数据、控制信号分拍传送，事务有明确的开始与结束。第 5 节的 I/O 总线会把同一套「事务」思路扩展到磁盘控制器上。

2. RAM：主存的积木原第 11–19 页

主存由 RAM 芯片搭出来。这一节先分清楚 SRAM 与 DRAM 两种芯片的脾气（原第 11–15 页），再拆开 DRAM 芯片看它内部怎么组织、怎么寻址（16–18），最后把 8 个芯片拼成一条 64 位宽的内存条（19）。

2.1 RAM 的关键性质原第 11 页

  • RAM 传统上封装成芯片；
  • 基本的存储单位通常是一个 cell（单元），一个 cell 存一位；
  • 多个 RAM 芯片组成一个内存（第 2.6 节会看到 8 个芯片拼成一条内存条）；
  • RAM 有两个品种：SRAM（静态 RAM）与 DRAM（动态 RAM）。

2.2 SRAM vs DRAM原第 12–13 页

每位晶体管数访问时间需要刷新？需要 EDC？成本典型用途
SRAM6 或 81×不需要可能需要100×cache（缓存）
DRAM110×需要需要1×主存、帧缓冲

（成本列是相对值：DRAM 为 1×，SRAM 约为它的 100 倍。EDC = 错误检测与纠正。）课件第 12 页把两者的物理差别画成两条：DRAM 是「1 个晶体管 + 1 个电容 / 位」，电容只能竖直方向做，而且电荷会漏，所以必须周期性刷新；SRAM 是「6 个晶体管 / 位」，只要通电就能无限期保持状态。为什么便宜的一定要刷新、贵的一定不刷新 —— 看的就是这两行。

2.4 DRAM 芯片内部：d×w 与超级单元原第 16 页

课件的说法（第 16 页原文）：d×w 的 DRAM 由 d 个「超级单元（supercell）」组成，每个超级单元 w 位。图里画的是 16 × 8 的 DRAM 芯片：4 行 × 4 列的超级单元阵列，每个超级单元 8 位，总共 16 × 8 = 128 位。一次访问只取一个超级单元 —— 所以地址 4 位、数据 8 位，地址被拆成行选择与列选择两半。

交互：DRAM 地址拆分器 —— 输入地址，看它选中哪个超级单元
行、列谁占高位？
课件第 16 页的图把 4 位地址分成两支各 2 位：高位给行（RAS）、低位给列（CAS）。真实芯片的行列位数由阵列形状决定（不是一个方阵就各占一半），但「地址先选行、再选列」这个两级结构是不变的 —— 下一页的 RAS / CAS 就是它的两个控制信号。

2.5 读一个超级单元：RAS 与 CAS原第 17–18 页

课件用两页演完一次读操作。目标是超级单元 (2,1) —— 第 2 行第 1 列：

Step 1(a) · 原第 17 页
行访问选通 RAS = 2：选中第 2 行
RAS = Row Access Strobe。
Step 1(b) · 原第 17 页
第 2 行从 DRAM 阵列复制到行缓冲（internal row buffer）
整行被搬进缓冲 —— 这一步很贵。
Step 2(a) · 原第 18 页
列访问选通 CAS = 1：选中第 1 列
CAS = Column Access Strobe；此时数据已在缓冲里。
Step 2(b) · 原第 18 页
超级单元 (2,1) 从缓冲复制到数据线，最终回到 CPU
「8 位数据」从这里离开芯片。
交互：读超级单元 —— 逐步执行 RAS / CAS，看图里高亮走到哪
行缓冲是「同一行连续访问便宜」的原因
一次访问要先把整行搬进缓冲，再按列取其中的一个超级单元。如果接下来的访问还落在同一行，行那一步就省了 —— 这正是 SDRAM「复用行地址（RAS, CAS, CAS, CAS）」的动机（原第 14 页），也是 DRAM 里最基本的空间局部性来源。

2.6 内存模块：8 个 DRAM 拼成一个 64 位字原第 19 页

课件第 19 页的模块是 64 MB 的内存模块，由 8 个 8M × 8 的 DRAM 组成：每个芯片存 8M 个 8 位超级单元，8 个芯片并联，一次访问各出一个超级单元，拼成一个 64 位字。8 个芯片收到的是同一个地址（同一个 (i, j)），差别只在于它们各自贡献这个字的哪 8 位 —— DRAM i 提供第 8i 到 8i+7 位。

为什么内存条要做成「8 芯片并联」
因为 DRAM 芯片的位宽（w = 8）追不上 CPU 的数据总线宽度（一次要 64 位）。把 8 个芯片并排、地址并联、数据错开接总线，就得到一个「一次出 64 位」的部件 —— 代价是每次访问 8 个芯片全都要动，所以一次主存访问消耗的能量与时间，是 8 个 DRAM 一起工作的时间。

3.2 磁盘驱动器里有什么原第 22 页

课件第 22 页用一张照片标出六个部件（照片本身是 Seagate 的素材，这里按文字列出）：

机械部分

盘片（platters）：真正存数据的地方，多个盘片叠在一根轴上；主轴（spindle）：带动盘片旋转；磁臂（arm）与驱动器（actuator）：把读写头在盘面上前后移动。

一句话

3.3 磁盘几何：面 → 磁道 → 扇区 → 柱面原第 23、24 页

  • 磁盘由盘片组成，每张盘片有两个面（surface）；
  • 每个面由同心圆环磁道（track）组成；
  • 每条磁道由扇区（sector）组成，扇区之间由间隙（gap）隔开；
  • 各盘面上对齐的磁道合起来叫一个柱面（cylinder）。
交互：磁盘几何 —— 切俯视图 / 柱面视图，看术语对应到哪一圈

3.4 容量：公式与一个例子原第 25–27 页

容量是能存的最多位数。厂商用 GB 表示，而 1 GB = 109 字节（十进制，不是 230）。容量由三个技术因子决定（第 25 页）：

每扇区字节数 × 平均每道扇区数 × 每面磁道数 × 每盘片面数 × 盘片数
  • 记录密度（bits/in）：一英寸磁道段上能塞多少位；
  • 道密度（tracks/in）：一英寸半径段上能塞多少条磁道；
  • 面密度（bits/in2）：记录密度与道密度之积。

为什么公式里写的是「平均每道扇区数」？因为现代磁盘把磁道分成若干记录区（recording zones）（第 26 页）：同一区内每条磁道的扇区数相同，由该区最内圈的周长决定；外圈的区因此每道扇区更多。于是不同区每道扇区数不同，算容量时只能用平均值。

交互：磁盘容量计算器 —— 默认值就是课件第 27 页的例题
为什么「容量」这一页值得慢慢算
容量公式是全讲里唯一一个能把几何量（扇区、磁道、面、盘片）变成字节数的式子。第 4 节的访问时间公式同样是从这些几何量里长出来的（每道扇区数决定转一个扇区要多久），所以这两页最好一起记。

4. 磁盘访问：从寻道到服务时间原第 28–42 页

课件用了十几页讲一次磁盘访问：第 28–29 页先说清「盘面在转、磁头在飞」，第 31–38 页用八张连续的图演示「读蓝色扇区，再读红色扇区」，第 39–42 页把它压成三段服务时间和一个能手算的公式 —— 以及一个令人清醒的结论：磁盘比 SRAM 慢了好几个数量级。

4.1 两个动作：旋转与寻道原第 28、29 页

  • 旋转：盘面以固定转速持续旋转（家用与服务器盘常见 7,200 RPM，第 40 页给数字）；
  • 读写头装在磁臂末端，靠一层薄薄的气垫「飞」在盘面上方 —— 不接触盘面；
  • 寻道（seek）：磁臂沿半径方向移动，就能把读写头定位到任意一条磁道上方；
  • 多盘片时，所有读写头连在一起同进同出，从一个柱面移到下一个柱面 —— 所以「换一条磁道」实际上是换一个柱面，这也解释了第 4.3 节的寻道时间为什么只算一次。

4.2 一次访问的九个步骤原第 30–38 页

课件第 30 页先把俯视图画出来（面由磁道组成，磁道切成扇区），第 31–38 页用八页连续图演示一次访问：磁头在某条磁道上方 → 盘面逆时针转 → 即将读到蓝色扇区 → 蓝色读完 → 红色请求排队 → 寻道到红色的磁道 → 旋转等待红色转到磁头下 → 红色读完。读这八页只要抓住一件事：每一次访问都要先定位（寻道 + 旋转等待），再传输，而只有传输那一段真正在搬数据。

交互：磁盘访问九步 —— 逐步看磁头、盘面与三段服务时间

Tavg transfer		把目标扇区里的位全部读出来(60 / RPM) × 1/(平均每道扇区数) s400 扇区/道 → 0.021 ms

公式里两个因子各有一句解释：1/2 是因为「目标扇区已经转到了头下」与「刚好错过、要再转一整圈」之间的平均等待是半圈；1/(平均每道扇区数) 是因为一整圈里平均分给每个扇区 1/(每道扇区数) 的时间。所以每道扇区数越多，一个扇区转过去的越快，传输时间越短 —— 这就是第 3 节容量与第 4 节时间之间的那根线。

5. 读一个磁盘扇区：I/O 总线与 DMA原第 43–46 页

第 1 节讲的是 CPU 与内存之间的总线；这一节把同一套「事务」思路接到 I/O 设备上。四页讲完一件事：CPU 只发一条命令就撒手不管了，真正搬数据的是磁盘控制器，搬完再由中断把 CPU 叫回来。

5.1 I/O 总线：设备挂在哪儿原第 43 页

  • CPU 芯片经系统总线接到 I/O 桥；I/O 桥的另一侧是内存总线（通主存）与 I/O 总线；
  • 挂在 I/O 总线上的设备：USB 控制器（接鼠标、键盘）、图形适配器（接显示器）、磁盘控制器（接磁盘），以及扩展槽（留给网卡这类其它设备）；
  • 第 1 节讲过的规则在这里照样成立：总线被多个设备共享，一次只能有一个事务在跑。

5.2 三步读完一个扇区原第 44–46 页

第 1 步 · 原第 44 页
CPU 把「命令 + 逻辑块号 + 目标内存地址」写进磁盘控制器的一个端口（地址）
CPU 只做这一件事，写完就转去做别的 —— 它不参与搬运。
第 2 步 · 原第 45 页
磁盘控制器读出该扇区，并执行一次 DMA（直接存储器访问）传输把它送进主存
DMA = Direct Memory Access：控制器自己当总线主设备，把数据直接写进内存，不经过 CPU 的寄存器。
第 3 步 · 原第 46 页
DMA 传输完成时，磁盘控制器用中断通知 CPU（在 CPU 上拉一个专门的「中断」引脚）
到这里 CPU 才知道「数据已经在你内存里了」。整个过程的代价是第 4 节算出的那 13 ms 量级。
交互：谁在干活 —— 切换三步，看 CPU 与磁盘控制器各自的状态
为什么要有 DMA 与中断
如果让 CPU 一个字节一个字节地把扇区搬进内存（程序控制 I/O），那 13 ms 里 CPU 就全被占住了。DMA 把「搬」这件事交给控制器，中断把「搬完了」这件事通知 CPU：CPU 只在开头写一条命令、结尾处理一次中断，中间的搬运它完全不用管。这也是后面讲文件与 I/O 时的基本分工。

6. 固态盘（SSD）：闪存的脾气原第 47–49 页

SSD 把第 2 节的闪存做成了「能顶替磁盘」的部件。它的接口看起来和磁盘一样（读写逻辑块），内部却完全是另一套规则：读写的单位是页，擦除的单位是块，而写过的页必须先擦掉所在块才能再写。这一节的三页都在讲这三条规则带来的后果。

6.1 页、块与翻译层原第 47 页

  • SSD 由闪存与闪存翻译层（flash translation layer, FTL）组成；FTL 对外假装自己是一个「按逻辑块读写」的磁盘；
  • 闪存按页 page 读写；若干页组成块 block（课件给的量级：页 512 B–4 KB，块 32–128 页）；
  • 一页只能在它所在的块被擦除之后才能再写；
  • 一个块在约 10 万次重复写之后磨损（第 15 页给过同一个数字）。
勘误：课件第 47 页把页大小印成「512KB to 4KB」
原文是「Pages: 512KB to 4KB, Blocks: 32 to 128 pages」。页比块还大是不可能的组合：若一页是 512 KB，那么 32 页的块就要 16 MB。闪存的页大小通行量级是 512 B – 4 KB（与课件第 66 页写的「Virtual Memory: 4-KB pages」同一量级），本页按 512 B–4 KB 呈现，并把「512KB」看作「512 B」的笔误 —— 下面 6.2 的写放大计算正是由「块 = 32–128 页」这个比例决定的。
交互：改写一页要动多少数据 —— 写放大与磨损的现算

6.2 性能：顺序快、随机慢、随机写更慢原第 48 页

课件给的是三星 970 EVO Plus 250 GB 的基准（第 48 页的链接是这台盘的实测页）：顺序读 2,126 MB/s、顺序写 1,880 MB/s、随机读 140 MB/s、随机写 59 MB/s。三条解释也在同一页：

  • 顺序访问快于随机访问（「存储层次里的共同主题」）；
  • 随机写更慢：擦一个块要很久（约 1 ms），而改写一个块里的一页需要把其它页复制到新块；
  • FTL 的对策是先把一连串小写攒起来，再一次性做块写入。
交互：吞吐量换算 —— 读/写 1 GiB 各要多久

6.3 与旋转磁盘的取舍原第 49 页

优点
  • 没有机械部件 → 更快、更省电、更抗震；
  • 顺序与随机的差距远小于磁盘（磁盘的随机访问要把寻道与旋转延迟付一遍又一遍）。
缺点
  • 会磨损：靠 FTL 里的磨损均衡（wear leveling）逻辑缓解 —— 控制器会搬动数据，让各个块的擦除次数平均；
  • 课件给的担保量级：一块盘可以写「600 次 × 容量」的字节数才磨损；
  • 2019 年时每字节约贵 4 倍，且相对成本还在下降。

应用：MP3 播放器、智能手机、笔记本；并越来越多地出现在桌面与服务器里。

勘误：型号 940 EVO Plus 应为 970 EVO Plus

8. 引用局部性（Locality）原第 52–57 页

局部性是全讲的支点：程序不会均匀地访问内存，它刚刚用过的数据和它附近的数据，很可能马上又要用。课件用五页讲它 —— 两页讲原理，三页让你练「看一眼代码就知道局部性好不好」这项手艺。

8.1 两条局部性原第 53 页

局部性原理（课件原文）
Programs tend to use data and instructions with addresses near or equal to those they have used recently. —— 这一句里已经藏了两半：「相等」是时间局部性，「相近」是空间局部性。
时间局部性（temporal locality）

刚被访问过的项，很可能在不久的将来再次被访问。循环里的循环变量、累加器、反复调用的同一条指令都属于这一类。

空间局部性（spatial locality）

地址相邻的项，倾向于在时间上被集中访问。顺序扫描数组、按顺序执行的指令序列都属于这一类 —— 它也解释了「块」为什么是缓存搬运的单位。

8.2 一眼看出一段代码的局部性原第 54 页

课件的例题是一段求和循环，然后逐条指出它的局部性来源：

sum = 0;
for (i = 0; i < n; i++)
  sum += a[i];
return sum;
引用的是什么怎么引用得到哪种局部性
数组元素 a[i]依次引用数组元素（stride-1 模式）空间局部性
变量 sum每次迭代都引用一次时间局部性
指令按顺序引用指令空间局部性
指令反复循环执行同一段时间局部性

课件第 55 页把话说得更直白：能看一眼代码就说出它的局部性好不好，是专业程序员的关键技能。下面的三小节就是课件的三道练习题，页面把它们做成了可以换参数重算的工具。

8.3 练习一：行优先扫描（答案是「好」）原第 55 页

int sum_array_rows(int a[M][N])
{
  int i, j, sum = 0;
  for (i = 0; i < M; i++)
    for (j = 0; j < N; j++)
      sum += a[i][j];
  return sum;
}

内层循环变的是最后一个下标 j，而 C 的二维数组是行优先存放的（a[i][j] 的线性地址是 i*N + j），所以访问是 stride-1 —— 空间局部性好。课件第 56 页又给了它的反面。

8.4 练习二：列优先扫描（答案是「不好」）原第 56 页

int sum_array_cols(int a[M][N])
{ /* 循环顺序换成 for (j…) for (i…) */ }

课件给的答案（第 56 页原文）是 Answer: no, unless… M is very small —— 列优先扫描时相邻两次访问在地址上相隔 N 个元素，同一个块里的其它元素要等很久才会被用到。至于「除非 M 很小」：M 很小时整个数组的工作集很小，块即使被很早取进来也还留在缓存里，坏处就显不出来了。

8.5 练习三：三维数组的循环排列（答案是「把 j 放到最内层」）原第 57 页

int sum_array_3d(int a[M][N][N])
{
  int i, j, k, sum = 0;
  for (i = 0; i < M; i++)
    for (j = 0; j < N; j++)
      for (k = 0; k < N; k++)
        sum += a[k][i][j];
  return sum;
}

课件的问题：能不能重排循环，让这个函数以 stride-1 扫描三维数组？答案（第 57 页原文）：Answer: make j the inner loop —— 因为 a[k][i][j] 里最后一个下标是 j，只有让 j 在内层以 1 递增，地址才会连续。

交互：循环顺序评测器 —— 换循环顺序，看访问序列的步长
课件没给 M、N 与块大小，这里怎么选
原课件三道题都只写了 M、N，没有具体数值，也没有说缓存块多大。本页默认 M = N = 4、块 = 4 个元素（一个块装得下一行），这样访问序列与块的对应关系一眼能数清；两个值都可以改 —— 把 N 调大，再对比两种循环顺序，「同一块被用到的间隔差多远」会变得非常直观。

9. 存储层次结构原第 58–61 页

第 7 节说差距在扩大，第 8 节说程序有局部性。第 58–61 页把两件事拼起来：把存储组织成一系列层次，每一层缓存下一层的一小部分 —— 于是便宜的大容量配上了接近最快那一层的速度。

9.1 三条基本性质原第 58 页

  • 越快的存储技术，每字节越贵、容量越小、功耗（发热）越高；
  • CPU 与主存之间的速度差距在持续扩大；
  • 写得好的程序往往有良好的局部性。

课件用一句话概括后两条的关系：这些性质 complement each other beautifully（互补得天衣无缝）—— 局部性意味着「快的那一小层够用」，速度差距意味着「必须要有那一小层」。于是自然得到存储层次的组织方式。

9.3 缓存与「大想法」原第 61 页

缓存（cache）的定义（课件原文）
A cache: a smaller, faster storage device that acts as a staging area for a subset of the data in a larger, slower device. （更小更快的存储设备，为更大更慢设备里的一部分数据充当暂存区。）
  • 存储层次的根本思想：对每一个 k，第 k 层那个更快更小的设备，充当第 k+1 层那个更大更慢设备的缓存；
  • 它为什么有效：因为局部性的存在，程序访问第 k 层数据的次数远多于访问第 k+1 层的次数 —— 所以第 k+1 层可以更慢，也因此可以更大、每字节更便宜；
  • 大想法（理想情形）：存储层次造出一个大容量存储池，它的价格接近最底下那层便宜存储，而给程序供货的速度接近最顶上那层快速存储。
这句话拆开就是本讲全部的设计目标
「容量按最便宜的算，速度按最快的算」不是魔法，而是局部性 + 逐层缓存两步换来的：外层提供容量，内层提供速度，中间每一层都要有命中率兜底。第 10 节把中间那一层单独拿出来讲 —— 缓存到底怎么工作。

10.1 缓存与内存的基本图景原第 62 页

10.2 命中与缺失原第 63、64 页

命中（hit）

要的数据块 b 已经在缓存里（第 63 页的例子：请求块 14，缓存的四个槽里正好有它）→ Hit!，直接从缓存取，不碰下一层。

缺失（miss）

块 b 不在缓存里（第 64 页的例子：请求块 12）→ 从内存把块取上来，再放进缓存。放进哪个位置（放置策略）与换掉哪一个（替换策略，被换掉的那块叫 victim）由缓存的规则决定。

10.3 三类缺失原第 65 页

缺失类型为什么会发生课件给的说法
冷缺失
cold / compulsory		这个块从来没被访问过，缓存里当然没有Cold misses occur because the cache is empty.
冲突缺失
conflict		缓存容量足够，但多个数据对象映射到了同一个槽Block i at level k+1 must be placed in block (i mod 4) at level k. … Referencing blocks 0, 8, 0, 8, 0, 8, … would miss every time.
容量缺失
capacity		活跃块的集合（工作集）大于缓存容量，装不下Occurs when the set of active cache blocks (working set) is larger than the cache.

课件的冲突缺失例子值得单独算一遍：映射规则是「第 i 个块放在第 i mod 4 个位置」，于是块 0 与块 8 永远抢同一个槽 —— 0, 8, 0, 8, 0, 8, … 这样的引用序列会每次都缺失，尽管缓存里一直有 3 个空槽。把「槽数」改成 2、再点一次上面的模拟器，就能看到三类缺失的分布跟着变。

一个容易判错的细节：第一次访问某个块永远是冷缺失
要看到容量缺失，序列里必须重复访问同一个块，而且两次访问之间工作集已经把缓存撑满 —— 例如 4 个槽、序列 0 1 2 3 4 5 0 1：前六个都是冷缺失（块 0…5 都是第一次出现），末尾的 0、1 才是容量缺失（访问过，但全相联也留不住）。所以「工作集大于缓存」描述的是重复访问时的命中失败，不是第一次访问。

11. 总结与测验原第 67 页

第 67 页只有三句话，却是整讲的骨架：差距在扩大 → 程序有局部性 → 用基于缓存的存储层次把差距补上。三句话分别对应第 1–7 节、第 8 节、第 9–10 节。

11.1 三句话的展开原第 67 页

差距在扩大

CPU 与内存、大容量存储之间的速度差距持续变大：2015 年的 CPU 时钟是 1985 年的 500 倍，而 DRAM 的访问时间只改善了 10 倍、磁盘 25 倍。

程序有局部性

写得好的程序会表现出时间局部性与空间局部性：反复用最近用过的项，也倾向于用地址相近的项。

用层次补差距

基于缓存的存储层次利用局部性把差距补上：每一层缓存下一层的一小部分，于是容量按最便宜的算、速度按最快的算。
