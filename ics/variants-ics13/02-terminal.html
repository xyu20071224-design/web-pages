北京大学《计算机系统导论》第 13 讲：缓存存储器（Cache Memories）。前几讲反复说「程序有局部性」——这一讲把这句话变成可计算的硬件：地址怎么被拆成 tag / 组索引 / 块内偏移，命中与缺失怎么判定，缺失又要付出多少周期，以及最后一件最有用的事：同一份矩阵乘法，为什么换个循环顺序就能快几倍。

本讲提纲（原第 2 页）
  1. 缓存的组织与工作方式
  2. 缓存的性能影响
  3. 存储器山（memory mountain）
  4. 重排循环以改善空间局部性
  5. 用分块（blocking）改善时间局部性
一句话核心

缓存把地址拆成三段——tag、组索引、块内偏移；命中与否只取决于「这一组里有没有一行的 tag 相等且 valid」。理解了这三段位和缺失的三种来源，就能看懂本讲后半段的全部性能数字：局部性其实是可量化的。

和前后讲的衔接

第 12 讲给出了存储层次（L0–L6）与「块」的概念；这一讲把 L1–L3 缓存打开看。第 14 讲接着用这套模型做代码优化。本讲是「性能」这条线的基础：后面所有优化都等价于「让访问模式更贴合缓存」。

1. 局部性、存储层次与缓存概念原第 3–9 页

这七页是「回顾」，但每一页都在为后面的量化做准备：局部性给出为什么缓存有用，存储层次给出缓存在哪一层，命中/缺失给出缓存的工作方式，三种缺失给出性能问题的分类。

1.1 局部性原理原第 3 页

局部性原理（principle of locality）：程序倾向于使用那些最近用过、或地址与最近用过的东西相近的数据与指令。它分两条：

  • 时间局部性（temporal locality）：最近被引用过的项，很可能在不久的将来被再次引用。
  • 空间局部性（spatial locality）：地址相近的项，倾向于在时间上被紧凑地引用。

下面把一段访问序列拆开看：相邻两次访问差多少、重复引用了多少次 —— 这两个统计量分别对应空间与时间局部性。

交互：局部性分析器 —— 输入访问序列，看每一步的步长与局部性
局部性不是「程序的善意」，而是「代码的结构」
循环体反复用同一批变量 → 时间局部性；按行扫数组、指令顺序执行 → 空间局部性。 这两条是缓存能起作用的前提：如果程序真的随机访问内存，任何缓存都救不了它。

1.3 通用缓存概念：命中、缺失、放置与替换原第 5–7 页

缓存是内存的一个子集，数据以「块（block）」为单位在内存与缓存之间搬运。处理器请求数据时：块在缓存里 = 命中（hit），直接用；不在 = 缺失（miss），要先把整块从内存取来放进缓存。下面用课件第 5–7 页那张图来做实验：内存 16 个块、缓存只能放 4 个块。

交互：请求一个块，看命中还是缺失、块被放到哪一格 （沿用课件第 8 页的放置规则：块 i → 第 i mod 4 格）
  • 放置策略（placement policy）：块 b 应该放进哪一行 —— 这一讲后面三节的直接映射 / 组相联 / 全相联都是在回答它。
  • 替换策略（replacement policy）：目标行已经被占用时，换出谁（victim）—— 随机、LRU 等。

1.4 三种缺失原第 8 页

缺失类型课件原话的展开
冷启动缺失
Cold (compulsory)		缓存一开始是空的，某个块第一次被引用时必然缺失。
容量缺失
Capacity		工作集（active cache blocks）比缓存还大 —— 缓存根本装不下。
冲突缺失
Conflict		缓存的第 k+1 层只允许块落在第 k 层的一个小子集（有时只有一行）里，例如「第 k+1 层的块 i 必须放到第 k 层的块 (i mod 4)」；缓存够大、但多个数据对象映射到同一格时，就会反复互相换出。课件举的例子：反复访问块 0、8、0、8…… 每次都缺失。

这三类的数目是可以当场算出来的：冷启动 = 该块第一次被引用；容量 = 换成本容量的全相联后仍然缺失的部分；冲突 = 换全相联后消失的缺失。

交互：3C 分解 —— 给一段访问序列，把三类缺失分开数
为什么课件要专门讲「冲突缺失」
冷启动缺失和容量缺失几乎无可避免，但冲突缺失是可以被设计消除的：提高相联度（一组多放几行）就能把「本不该互相挤走」的块留住。 第 3 节会把同一个访问序列在 1/2/4/8 路下的缺失数并排算出来 —— 课件第 13 页与第 17 页那两次模拟的差别（4 次缺失 vs 3 次缺失）就来自这里。

1.5 缓存存储器与典型系统结构原第 9 页

  • 缓存是又小又快的 SRAM，由硬件自动管理，程序看不见它。
  • 它保存主存中被频繁访问的块。
  • CPU 取数据时先看缓存。
典型系统结构（课件第 9 页的图）本讲关心什么
CPU 芯片内有：寄存器堆（Register file）、缓存（Cache memory）、ALU、总线接口（Bus interface）缓存在芯片上，和寄存器堆、ALU 并列 —— 它是「CPU 与内存之间的那一段」
芯片外：系统总线 / 内存总线（System bus · Memory bus）→ 主存（Main memory）；总线接口再通到 I/O 桥与其它设备缓存缺失时要走这条总线，代价是 50–200 个周期（第 6 节）

3. 组相联与通用结构原第 14–19 页

把「每组一行」放宽成「每组 E 行」，就得到E 路组相联（E-way set associative）缓存。代价是组内要逐行比较 tag、还要多一套替换策略；回报是冲突缺失大幅减少。最后课件给出三参数的通用结构，和一次读的三步流程。

3.1 E 路组相联（课件用 E = 2 举例）原第 14–16 页

课件第 14–16 页把直接映射那张图改成了「每组两行」：地址仍然只决定去哪个组，但组里有两行，tag 要同时比较两行（compare both）—— 任一行匹配且 valid = 1 就是命中。两行都匹配不上时，才需要挑一行换出：课件列出的替换策略是随机、最近最少使用（LRU）等。

3.4 缓存读的三步与替换原第 19 页

课件第 19 页把「读」正式写成三步：① 定位组（set index）→ ② 组内比较 tag（+ valid）→ ③ 按块内偏移取数。2.1 节的交互把这四步（含最后的结论）逐块展开。补充三点：

  • 命中要求「tag 匹配」与「该行 valid = 1」同时成立 —— 只有 tag 相等但行是空的（v = 0）不算命中。
  • 全相联（fully associative）是 E = S 的极端：只有一组，任何块都能放在任何行，替换策略直接决定换谁 —— 它的冲突缺失为 0，这也是第 1.4 节 3C 分解的参照物。
  • 直接映射是 E = 1 的另一个极端：没有选择，替换策略也用不上。

4. 写策略原第 20–21 页

读只有一个答案，写有四个：写命中时是「写直达」还是「写回」，写缺失时是「写分配」还是「非写分配」。这两个维度决定了内存流量、dirty 位的存在，以及课件第 21 页那段流程。

4.1 四个选择原第 20 页

课件先指出为什么写比读麻烦：同一份数据存在多份副本（L1、L2、L3、主存、磁盘），改了一份就得考虑其它几份。

场合选择含义
写命中
write-hit		写直达（write-through）立刻写内存。
写回（write-back）推迟到该行被替换时才写内存。为此每行需要一个 dirty 位：被写过就置 1。
写缺失
write-miss		写分配（write-allocate）先把块取进缓存、再在缓存里改 —— 如果后面还会写同一位置，这笔搬运是划算的。
非写分配（no-write-allocate）直接写进内存，不把块搬进缓存。

课件给出的「典型搭配」是两对：写直达 + 非写分配，以及写回 + 写分配。

交互：写策略实验台 —— 同一段读写序列，四种组合的访存次数
为什么「写直达 + 非写分配」在真实机器上很常见

5. 索引位：为什么用中间位原第 22–25 页

课件用四页回答一个小问题：地址里那 s 位「组索引」该取哪几位？答案是中间位（紧挨着块内偏移的那几位），理由是空间局部性；如果用高位，局部性好的程序反而会大量冲突。

5.1 两种索引方式原第 22、24、25 页

标准做法：中间位索引 TTSSBB

地址形如 TT SS BB：TT = tag（高位）、SS = 组索引（中间）、BB = 块内偏移（低位）。 连续地址落在不同组 → 充分利用空间局部性。

另一种做法：高位索引 SSTTBB

地址形如 SS TT BB：SS = 组索引（高位）、TT = tag（中间）、BB = 偏移。 连续一段地址全挤进同一个组 → 空间局部性好的程序会产生大量冲突。

课件第 23 页给了一个极小的例子：64 字节内存、6 位地址、16 字节的直接映射缓存、块大小 4 字节 → 16/4 = 4 组，于是 2 位 tag、2 位索引、2 位偏移。下面两种索引都真的跑一遍：

交互：两种索引并排跑 —— 同一段序列，谁的缺失少
本例的分水岭
缓存只有 4 行。反复访问前 4 个块（0、4、8、12 循环）时：中间位索引把它们分到 0/1/2/3 四个组，一次冷启动之后全部命中； 高位索引把块 0、4、8、12 都放进同一个组（6 位地址 0000xx–0011xx 的高 2 位都是 00），一组只有一行 → 每次都缺失，反复换出对方。 点上面的按钮，两种索引的缺失数会直接并排显示出来。
为什么硬件偏爱中间位
组索引与块内偏移连在一起，意味着「同一块里的连续访问」只在偏移位变化，组索引不变 —— 一次缺失换来 B 个字节的连续命中。 若把索引放到高位，相邻的块会互相抢同一个组，硬件再快也救不回被换出去的数据。课件第 24 页的结论就是这一句：makes good use of spatial locality。

7. 存储器山原第 32–35 页

从这一节开始，把前面所有参数压成一个数字：读吞吐（read throughput / read bandwidth）——每秒从内存读出多少字节。它随工作集大小和步长变化，画出来像一座山：山脊是时间局部性，坡面是空间局部性。

7.1 读吞吐与存储器山原第 33 页

  • 读吞吐（read throughput）：每秒从内存读出的字节数（MB/s）。
  • 存储器山（memory mountain）：把实测的读吞吐画成空间局部性与时间局部性的函数所得的那张曲面 —— 一种紧凑地刻画存储系统性能的方式。
山脊（ridges）= 时间局部性

沿工作集大小走：工作集小到装得进 L1，数据由最快的层级供数（山顶）；装不进 L1、只装得进 L2，就低一档；再往上是 L3、主存。 每到一个层级的容量边界就出现一道「台阶」——这些台阶连起来就是山脊。

坡面（slopes）= 空间局部性

沿步长走：步长为 1 时一块 64 字节里的 8 个 double 全被用上，吞吐最高；步长越大，一块里被用到的比例越低， 直到步长 ≥ 8（每访问一个元素都要换一块），吞吐落到底，曲线变平。

交互：存储器山切片 —— 挑工作集大小与步长，看数据落在哪一级

7.2 测试函数：怎么把这座山测出来原第 34 页

课件的测量方法本身很简单，但有两个讲究：4×4 循环展开（让循环开销不干扰吞吐），以及先热身一次再计时（保证缓存状态可复现）。

long data[MAXELEMS];  /* 全局数组，遍历它 */
int test(int elems, int stride) {
  long i, sx2=stride*2, sx3=stride*3, sx4=stride*4;
  long acc0 = 0, acc1 = 0, acc2 = 0, acc3 = 0;
  long length = elems, limit = length - sx4;
  /* Combine 4 elements at a time */
  for (i = 0; i < limit; i += sx4) {
    acc0 = acc0 + data[i];    acc1 = acc1 + data[i+stride];
    acc2 = acc2 + data[i+sx2];  acc3 = acc3 + data[i+sx3];
  }
  /* Finish any remaining elements */
  for (; i < length; i++) { acc0 = acc0 + data[i]; }
  return ((acc0 + acc1) + (acc2 + acc3));
}
mountain/mountain.c
测量流程（课件第 34 页右侧）为什么
对每一组 elems 与 stride：1. 先调用一次 test() 热身缓存第二次调用时缓存里已经是「稳态」，测到的是缓存而不是冷启动
2. 再调用一次 test()，测量读数吞吐（MB/s）读的字节数 = 访问到的元素数 × 8 字节；除以耗时即吞吐
把「山」的两个方向对上号
elems 决定工作集大小（沿山脊方向），stride 决定空间局部性（沿坡面方向）。 固定 elems 扫 stride，得到坡面；固定 stride 扫 elems，跨过 L1/L2/L3 的容量边界时就出现山脊的台阶。

9. 分块：用时间局部性换缺失原第 48–55 页

循环重排只能把列优先的 1.0 换成行优先的 0.25；分块（blocking）更进一步：把矩阵切成 B × B 的小块，让三个小块同时待在缓存里反复用，把总缺失从 (9/8)n³ 降到 n³/(4B)。

9.1 分块版矩阵乘法原第 49、52 页

void mmm(double *a, double *b, double *c, int n) {
  int i, j, k, i1, j1, k1;
  for (i = 0; i < n; i+=B)
    for (j = 0; j < n; j+=B)
      for (k = 0; k < n; k+=B)
        /* B x B mini matrix multiplications */
        for (i1 = i; i1 < i+B; i1++)
          for (j1 = j; j1 < j+B; j1++)
            for (k1 = k; k1 < k+B; k1++)
              c[i1*n+j1] += a[i1*n + k1]*b[k1*n + j1];
}
matmult/bmm.c（自增已按本页勘误修正）
分块在做什么

朴素的 ijk 把 C 的每个元素都按列扫一遍 B（列优先，1.0 次缺失/访问）；分块后，每次内层三重循环只处理三个 B × B 小块： C 的一小块、A 的一小块、B 的一小块。三个小块加起来 3B² 个元素 —— 只要这份工作集装得进缓存，它们就能一直待在缓存里被反复使用（每个元素平均用 B 次）。 这用的是时间局部性，和 8 节的循环重排（空间局部性）互补。

9.3 分块小结原第 55 页

两个公式

不分块：(9/8) · n³

分块：1/(4B) · n³

所以 B 越大越好，但必须守住 3B² < C。

差距为什么这么大
  • 矩阵乘法本身就带有内在的时间局部性：输入数据 3n² 个，而计算量 2n³ —— 每个数组元素都被用了 O(n) 次；
  • 但程序必须写对才能兑现这份局部性：朴素循环把「用过就能再用」的数据提前扔出了缓存。

勘误：第 52 页分块代码的自增写错了变量
原课件第 52 页印出的三层内层循环是 for (i1 = i; i1 < i+B; i++)、for (j1 = j; j1 < j+B; j++)、for (k1 = k; k1 < k+B; k++) —— 自增的是外层循环变量 i / j / k，而不是内层下标 i1 / j1 / k1。 这样一来 i1 从头到尾不变、而条件里的 i 却在增长，最内层循环永远退不出去（内层下标 k1 不变、k 一直加，条件恒真）； 而且它写成的下标固定不变，也根本实现不了注释里写的 B x B mini matrix multiplications。
本页按 i1++ / j1++ / k1++ 呈现，因为原课件的注释与第 53–54 页的整套缺失分析都以「小块被反复使用」为前提，只有修正后的写法才与之自洽。下面的演示把两种写法都跑给你看。

9.4 缓存总结原第 56 页

  • 缓存对性能有显著影响；
  • 这是可以主动利用的：
  • 盯着内层循环 —— 绝大部分计算与访存都发生在那里；
  • 用 stride 1 顺序读数据对象，把空间局部性拉满；
  • 一个数据对象从内存取来之后，尽可能多用几次，把时间局部性拉满。

10.4 容量效应与块大小效应原第 62–64 页

容量效应（第 62 页）

把存储器山沿 stride = 8 切一刀（固定步长，只改工作集大小），得到一条「纯粹的时间局部性曲线」： 横轴是工作集大小，从最大的 128m 往左走到 1 MB 以下，曲线上依次出现 Main Memory → L3 → L2 → L1 四级台阶。 这条切片把「山脊」单独抽了出来。

块大小效应（第 63 页）

固定工作集（size = 128K），横轴改成步长 s（1–12）： 实测曲线从 s1 一路下滑，并在图上标了两条参考线 —— Miss rate = s/8（步长小于 8 时，一块 64 字节里被用到的比例）与 Miss rate = 1.0（每访问一次就换块，曲线走平）。

把 65 页压成三件事：缓存怎么组织的（地址三段位 + S/E/B + 三种缺失）、缓存怎么工作的（命中判据 + 写策略）、怎么利用它（局部性 → 循环重排 → 分块）。

11.1 一页总结

组织
  • 地址 = tag | 组索引 | 块内偏移；
  • S 组 × E 行 × B 字节，C = S × E × B；
  • 三种缺失：冷启动、容量、冲突。
工作方式
  • 读三步：定位组 → 比较 tag（含 valid）→ 按偏移取数；
  • 写四选一：写直达/写回 × 写分配/非写分配；
  • 性能三指标：缺失率、命中时间、缺失代价。
优化
  • 内层循环里用 stride 1（空间局部性）；
  • 取来的数据尽量多用几次（时间局部性）；
  • 分块把缺失从 (9/8)n³ 降到 n³/(4B)（3B² < C）。
本讲的量化承诺
「这段代码局部性好」不再是形容词：缺失率 = min(s/8, 1)、每轮内循环缺失 = 0.25 + 1.0 + 0.0、总缺失 = (9/8)n³ 或 n³/(4B) —— 全都是能当场算出来的数， 也全都能在页面里用模拟器复现（第 2、3、8、9 节的工具）。
