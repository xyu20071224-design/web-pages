1. 小数的二进制表示原第 3–6 页

先搞清楚「二进制小数点」右边那些位是什么意思，这是理解浮点数的地基。

1.1 权重展开

一个二进制数 bi bi−1 … b2 b1 b0 . b−1 b−2 b−3 … b−j 的每一位都带着 2 的幂次权重：

权重：… 2i … 4   2   1  .  1/2   1/4   1/8   … 2−j

也就是：小数点左右两侧的位，分别表示 2 的正幂和 2 的负幂。整个数是一个有理数：

值 = Σ bk × 2k

例：1011.1012 = 8 + 0 + 2 + 1 + 1/2 + 0 + 1/8 = 11.625

1.2 交互：二进制小数 ⇄ 十进制

1.3 交互：十进制小数 → 二进制

关键结论
只有形如 x / 2k 的数才能被精确表示；其他有理数会得到无限循环的二进制小数。例如 1/10 = 0.0̅0̅0̅1̅1̅（循环节 0011），这也正是爱国者导弹出问题的根源。

  • 1/2 + 1/4 + 1/8 + … + 1/2i + … → 1.0，记作 1.0 − ε。

2. IEEE 754 浮点表示原第 8、10–15 页

IEEE 754 把「科学计数法」编码进定长的二进制位串。理解 exp 与 frac 两个字段是全部关键。

2.1 从二进制科学计数法说起

1.1101101101101 × 213

一个二进制科学计数法数由两部分构成：有效数字 significand（1.1101101101101）和 指数 exponent（13）。规格化（normalized）之后，有效数字的整数部分总是 1。

2.2 数值形式

v = (−1)s × M × 2E
  • 符号 s：决定正负。
  • 有效数字 M：通常落在 [1.0, 2.0) 区间的小数值。
  • 指数 E：以 2 的幂次对数值加权。

例：15213 = (−1)0 × 1.1101101101101 × 213

2.3 编码布局

s  |  exp  |  frac
  • 最高位（MSB）是符号位 s。
  • exp 字段编码 E，但不等于 E（存在偏移 bias）。
  • frac 字段编码 M，但不等于 M（隐含前导 1）。

精度选项

2.4 「规格化」数值

条件：exp ≠ 000…0 且 exp ≠ 111…1。

  • 指数编码为偏移值：E = Exp − Bias，其中 Exp 是 exp 字段的无符号值，Bias = 2k−1 − 1（k 是指数字段位数）。
    • 单精度：Bias = 127（Exp: 1…254，E: −126…127）
    • 双精度：Bias = 1023（Exp: 1…2046，E: −1022…1023）
  • 有效数字带隐含前导 1：M = 1.xxx…x2，其中 xxx…x 就是 frac 字段的位。
    • frac = 000…0 时取最小 M = 1.0
    • frac = 111…1 时取最大 M = 2.0 − ε
    • 相当于白赚一位精度。
交互：把 15213.0 编码成单精度（可逐步展开）

4. 三类浮点数原第 13、16–17 页

非规格化值、规格化值、特殊值 —— 三种情况覆盖了 exp 字段的全部取值。

4.1 非规格化值（Denormalized）

条件：exp = 000…0。

  • 指数取值：E = 1 − Bias（注意不是 0 − Bias）。
  • 有效数字隐含前导 0：M = 0.xxx…x2，xxx…x 是 frac 字段的位。
情形一：frac = 000…0

表示零值。注意存在两个不同的零：+0 与 −0。
为什么需要 −0？因为它保留了符号信息，让 1.0/−0.0 = −∞ 这样的运算能表达「从负方向趋近 0」。

情形二：frac ≠ 000…0

表示最接近 0.0 的数，且在 0 附近是等间距的。这一设计保证了「下溢」是渐进发生的，而不是突然变成 0。

4.2 特殊值（Special Values）

条件：exp = 111…1。

情形一：frac = 000…0 → ±∞
  • 表示无穷，由运算溢出产生。
  • 正负无穷都有。
  • 1.0/0.0 = −1.0/−0.0 = +∞
    1.0/−0.0 = −∞
情形二：frac ≠ 000…0 → NaN
  • Not-a-Number，「不是一个数」。
  • 当运算结果无法确定数值时使用。
  • 如 sqrt(−1)、∞ − ∞、∞ × 0

4.3 可视化：编码的分布

把所有编码按数值排成一列，可以看到 IEEE 编码的整体结构（原第 23 页）：

−∞  ·  负规格化 −Normalized  ·  负非规格化 −Denorm  ·  −0 +0  ·  正非规格化 +Denorm  ·  正规格化 +Normalized  ·  NaN  ·  +∞

越靠近 0，编码越密集 —— 这就是非规格化值的作用。

5.3 IEEE 编码的两个特殊性质

① 浮点零与整数零相同

所有位都为 0 时既是浮点 +0.0 也是整数 0，这让内存清零天然得到浮点零。

② 几乎可以用无符号整数比较
  • 必须先比较符号位；
  • 必须考虑 −0 = 0；
  • NaN 有麻烦：它会比任何其他值都「大」，比较结果应该是什么？
  • 其余情况都没问题：非规格化 vs 规格化、规格化 vs 无穷，编码顺序与数值顺序一致。

6. 舍入原第 31–34 页

浮点运算的本质：先精确计算，再把它塞进有限的位宽里 —— 塞不进去的部分就要舍入。

x +f y = Round(x + y)     x ×f y = Round(x × y)

基本思路：先算出精确结果 → 让它适应目标精度。过程中可能因为指数过大而溢出，也可能需要舍入才能装进 frac 字段。

6.1 四种舍入模式

模式$1.40$1.60$1.50$2.50−$1.50
向零舍入 Towards zero$1$1$1$2−$1
向下舍入 Round down（−∞）$1$1$1$2−$2
向上舍入 Round up（+∞）$2$2$2$3−$1
就近舍入到偶数 Nearest Even（默认）$1$2$2$2−$2

* 就近舍入：优先取最近的值；如果正好在中间（half-way），则取最低位为偶数的那个。

6.2 为什么默认是「就近舍入到偶数」

  • 不写汇编几乎无法切换到其他模式。
  • 其他模式在统计上有偏：一组正数求和会系统性地被高估或低估。
  • 「到偶数」让一半的情况向上、一半向下，长期偏差相互抵消。

这套规则同样适用于十进制小数位：正好在半途时，让最低有效位变成偶数。

  • 舍入位置右侧的位为 100…2 时，正好在「半途」。

7. 浮点乘法与加法原第 35–36 页

两个运算的步骤几乎对称：算出精确结果 → 规格化 → 舍入。

7.1 浮点乘法

(−1)s1 M1 2E1 × (−1)s2 M2 2E2

精确结果：(−1)s M 2E，其中

  • 符号：s = s1 ^ s2（异或）
  • 有效数字：M = M1 × M2
  • 指数：E = E1 + E2

修正：若 M ≥ 2，M 右移一位、E 加 1；若 E 超出范围则溢出；最后把 M 舍入到 frac 的精度。实现上最繁重的部分就是两个有效数字的乘法。

例题（4 位有效数字）
1.010 × 22 × 1.110 × 23 = 10.0011 × 25
= 1.00011 × 26  →  舍入到 4 位 → 1.001 × 26

7.2 浮点加法

(−1)s1 M1 2E1 + (−1)s2 M2 2E2

假设 E1 > E2，先把两个数的小数点对齐（把较小指数的那个数右移 E1 − E2 位），再做带符号的相加。

修正：若 M ≥ 2，右移一位、E 加 1；若 M < 1，则左移 k 位、E 减 k；若 E 超出范围则溢出；最后舍入 M。

例题
1.010 × 22 + 1.110 × 23 = (0.1010 + 1.1100) × 23
= 10.0110 × 23 = 1.00110 × 24  →  舍入 → 1.010 × 24
交互：4 位有效数字的浮点加法器（逐步演示）

8. 浮点运算的数学性质原第 37–38 页

浮点加法满足交换律，但不满足结合律；乘法满足交换律，但不满足结合律、也不满足分配律。这是编译器与数值程序员的噩梦。

性质浮点加法浮点乘法说明
封闭性是是但可能产生 ∞ 或 NaN
交换律是是a + b = b + a
结合律否否溢出 + 舍入不精确
单位元是（0）是（1）0 是加法单位元，1 是乘法单位元
逆元几乎无此性质除 ∞ 与 NaN 外都成立
分配律否溢出 + 舍入不精确
单调性几乎几乎a ≥ b ⇒ a + c ≥ b + c，除 ∞ 与 NaN 外成立

8.1 反例：亲手验证

点击用 JavaScript 的 double 实测这些反例
表达式实际结果违反的性质

单精度 float 与双精度 double 的差别

课件里「(3.14+1e10)−1e10 = 0」这个经典例子其实是 float 的结果。float 在 1e10 附近的间距是 210 = 2048，3.14 被彻底抹平；而 double 的间距只有约 1.1 × 10−6，3.14 能部分保留下来。用 Math.fround 模拟单精度运算即可验证：

结论：结合律在两种精度下都不成立，只是「错成什么样」取决于精度。

加法不满足结合律
单精度 float：
  (3.14 + 1e10) − 1e10 = 0
  3.14 + (1e10 − 1e10) = 3.14

3.14 加到大数上时被完全舍掉（有效数字不够长），而大数先自减为 0 后，3.14 得以保留。注意这是 float 的结果：float 在 1e10 附近的间距是 2048，3.14 直接被抹平；换成 double 间距只有约 1.1 × 10−6，3.14 能部分保留，结果就不再是 0。

乘法不满足结合律、分配律
(1e200 × 1e200) × 1e−20 = inf
1e200 × (1e200 × 1e−20) = 1e200

1e200 × (1e200 − 1e200) = 0.0
1e200 × 1e200 − 1e200 × 1e200 = NaN

前者因为中间结果溢出成 ∞；后者因为 ∞ − ∞ 得到 NaN。

给程序员的忠告
不要默认 (a+b)+c == a+(b+c)，也不要指望编译器能自由重排你的浮点表达式 —— 它不允许这么做。
勘误：课件里的 1e20 应为 1e200
原课件这一页写的是 1e20，但 double 能表示到约 1.8 × 10308，1e20 × 1e20 = 1e40 根本不会溢出，也就得不到课件声称的 inf 和 NaN。把它换成 1e200 后，四个结果（inf、1e200、0.0、NaN）就全部成立 —— 可以点上面的按钮亲手验证。本页按 1e200 给出。

9. C 语言中的浮点原第 40–41 页

C 只保证两个精度层次，转换规则则充满陷阱。

9.1 两个精度层次

float

单精度，32 位。

double

双精度，64 位。

9.2 转换 / 强制类型转换

在 int、float、double 之间转换会改变位表示。

转换行为
double / float → int截断小数部分（相当于向零舍入）。超出范围或为 NaN 时行为未定义，一般会得到 TMin。
int → double精确转换，只要 int 的字长不超过 53 位。
int → float会按照当前舍入模式进行舍入。

11. 总结与测验原第 42、48 页

11.1 总结

  • IEEE 浮点具有清晰的数学性质。
  • 它表示形如 M × 2E 的数。
  • 可以脱离具体实现去推理运算 —— 就好像先以无限精度计算，然后再舍入。
  • 但它不等于实数运算：违反结合律与分配律，给编译器和严肃的数值程序带来麻烦。
